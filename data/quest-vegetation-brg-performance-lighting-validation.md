### 概要

本文记录的是 2026-08-19 四组 Quest 3S 历史完整系统 A/B/A：初始 BatchRendererGroup（BRG）→ 普通 GameObject（GO）→ 回切 BRG。BRG 是 Unity 的低层批量渲染接口；普通 GO 路径则展开 `GameObject + Transform + MeshRenderer + LODGroup`。两侧还使用不同的运行时光照表达，因此这不是只替换 Draw API 的微基准，也不验证当前 32 B ABI（应用二进制接口，即 C# 与 Shader 共享的逐株数据协议）。

解释结果前必须保留下列条件：只有 15% Box 保存了三段同一 PID（Process Identifier，操作系统进程标识）；同一 PID 支持“三段位于同一进程”，但不能证明姿态、温度或其它条件相同。高密度真实草与大 Box 只有同一应用会话说明，没有 PID；稀疏组只有顺序窗口和操作者切换说明。15% Box 的普通 GO 段还使用了更高的 GPU 档位与时钟。历史材料没有保存 `CPU+GPU ms`、`CPU %` 和 `GPU %` 的精确定义、百分比归一化基准、窗口聚合公式或逐样本序列，因此这些字段只能按保存值描述，不能解释为可相加的独立 CPU/GPU 时间或已知定义的利用率。

在这些限制下，四组数据支持两条有限结论：Box 的同包 A/B/A 中，普通 GO 段的 CPU 侧相关字段表现出更高总压力；BRG 不会自动减少已进入视野的顶点、三角形、双面栅格化、Alpha Clip 和重复像素覆盖。8192 株、单株 640 顶点/704 三角形的真实草在 8192/8192 可见时，三段均约 20 FPS，历史 `GPU %` 字段约 99%，这一组合与 GPU 饱和及几何/覆盖主导一致，但不足以证明单一 GPU 瓶颈或拆分顶点、三角形和片元占比。

把真实草换为 24 顶点/12 三角形 Box 并缩小屏幕覆盖后，BRG 段达到 83–91 FPS；但几何变体来自不同 APK（Android Application Package，即一次可安装构建产物），两个 Box APK 还存在 31.111% 未解释的体积差异。跨构建结果只能作为几何与覆盖成本重要的相关性证据，不能称为严格单变量因果实验。

### 内容

#### 研究问题与证据层级

本文把 2026-08-19 的四组 Quest 3S 数据当作历史观察研究，而不是当前版本基准。它回答三个问题：同一测试构建内切换完整 BRG 与普通 GO 路径时，保存指标如何变化；跨构建改变网格与屏幕覆盖后，结果与哪些瓶颈解释一致；为什么这些旧数据不能验证已经更换逐株 ABI、光照表达和运行时组织的当前实现。

当前 ABI 的 Editor 证据绑定到 Unity `2022.3.62f3`、Direct3D11 和 Unity.Mathematics `1.3.2`；历史数据来自旧版 Quest 设备路径，两者不能拼接为一次验证。因此本文只描述历史设备观察及其边界，不代表当前 ABI、Shader 或运行链的设备性能。

证据强度分为三层，后文所有结论都受这一层级约束：

| 证据 | 可以支持 | 不能支持 |
|---|---|---|
| 同一历史测试构建内的 BRG→GO→BRG 汇总窗口 | 观察模式切换前后指标是否同向变化、回切是否恢复 | 没有逐样本序列时的显著性、方差、异常值和严格因果效应 |
| 保存的场景、网格、相机和设备配置 | 解释一次实验的大致工作量与适用范围 | 未保存字段的等价性，或不同 APK 之间只有一个变量变化 |
| 当前源码与 Editor ABI 证据 | 说明历史实现与当前实现已经不同 | 当前实现的 Quest Vulkan 性能、功耗或热稳定性 |

#### 一、测试条件、指标定义与直接结果

#### 二、测试对象、场地和相机参考尺度

**真实草。** 单株 LOD0 为 640 顶点、704 三角形、2112 索引、1 个 SubMesh。实际几何 Root Space AABB 为 `0.3154 × 0.4634 × 0.3642` 米，实例缩放为 10.8–12.6 倍，世界尺寸约为 X `3.41–3.97` 米、Y `5.00–5.84` 米、Z `3.93–4.59` 米。材质使用 Alpha Clip 与 `Cull Off`。本记录中的“真实草”只指这一测试模型。

**高密度场地。** 共 8192 株、50 个 Heap；Heap 是运行时 Cell 内用于空间组织、加载和剔除的分块。实例中心范围约 `158.99 × 78.99` 米，面积 `12558.22` 平方米，平均密度 `0.652` 株/平方米，等效平均中心间距约 `1.24` 米，XZ 世界空间最小中心距离为 `1.01428664` 米。边长只展示到小数点后两位，面积使用未舍入的原始边界差计算，因此不能把两个显示值相乘作为精确面积复算。XR Rig 位于 `(0,100,0)` 并绕 X 轴 90°俯视，相机在 Rig 下保留约 1.6 米局部高度，头显跟踪仍启用。Near/Far 为 `0.03/300` 米，单眼 FOV（水平 × 垂直）约 `90° × 98°`，Eye Buffer `1536 × 1760`、Viewport `100%`，刷新率 90 Hz，质量档为 Performant。Heap 加载/卸载范围为 `180/200` 米，LOD 为单档、Cull 0、LOD Bias 100。探针源为 Bakery L2；三盏灯均已烘焙，运行时实时灯数量为 0。

真实草组保存了 Active Heaps `50/50`、Frustum Candidates `8192`、Visible After LOD `8192/8192`、植被 BRG `BatchDrawCommand = 1`、GO Visible `8192/8192`。`BatchDrawCommand` 是 BRG 剔除输出中描述一次批量绘制工作的命令记录。现有证据只说明 BRG 侧记录了一个植被命令；普通 GO 侧没有保存可比的提交命令计数，因此不能据此推出 BRG 比 GO “减少了提交命令”。该值也不表示整个 GameView 只有一个 Draw Call。

**稀疏大场地。** 总量 8192 株、1024 个 Heap。生成规则是 128 列 × 64 行；Z 方向名义跨度精确为 `(64-1) × 8 = 504` 米，X 方向用同一 504 米跨度分布，因此未加抖动的名义网格为 `504 × 504` 米。名义密度为 `8192 / (504 × 504) ≈ 0.03224994` 株/平方米，简写为 `≈0.03225`；它不是实际占地或地面面积密度。每个中心在 X/Z 还叠加最多 `±0.30` 米的确定性抖动，SceneAsset 实例中心实际范围约 `504.59 × 504.60` 米，地面边长为 `514` 米；显示网格间距 X `3.97` 米、Z `8.00` 米。XR Rig 可移动，Near/Far 为 `0.03/1000` 米，FOV（水平 × 垂直）约 `104.09° × 80°`，刷新率 90 Hz，Heap 加载/卸载范围 `150/175` 米，LOD Bias/Cull 为 `0.2/0.005`。设备三段没有保存姿态、Eye Buffer、质量档、光照配置和实际可见数；历史构建也不能与当前生成器建立源码级身份绑定。

编辑器默认姿态曾记录 Active Heaps `320/1024` → Frustum Candidates `2595` → Visible After LOD `520/8192`；该 520 不代表三段设备采样期间的实际可见数。

#### 三、两种 Box 代理准确代表什么

大尺寸 Box 与 15% 尺寸 Box 都是 24 顶点、12 三角形、36 索引。大尺寸 Box 的实际几何 Root Space AABB 与真实草相同；15% 尺寸 Box 的实际几何 AABB 为 `0.0473 × 0.0695 × 0.0546` 米，缩放后世界尺寸约 X `0.51–0.60` 米、Y `0.75–0.88` 米、Z `0.59–0.69` 米。最大旋转无关 XZ 外接圆直径为 `0.9105374` 米，小于 XZ 世界空间最小中心距 `1.01428664` 米，因此**静态低重叠 Box 在任意 Y 轴旋转下的水平包络**不相交；该门禁不含 Shader 风摆或其它运行时顶点位移。BRG 保守剔除 Bounds 仍保持真实草大小。

人工观察者在头显全景构图中记录两组 Box 的 8192 个实例全部进入画面，设备截图保存了该构图；三段未保存统一机器可见计数。头显观察与截图支持“全部入画”的观察结论，但不等价于程序化 `8192/8192` 可见计数。

高密度真实草到大尺寸 Box 的实验设计复用同一场景、SceneAsset、8192 个实例及其布局、材质链、LOD 参考、光照模式、场景 SH、相机和质量档，只替换 Prototype Mesh；但历史真实草构建缺少可核对的布局与光照签名，因此跨构建比较不是严格可复算的单变量实验。替换本身还同时改变网格拓扑、草叶轮廓、Alpha Clip 覆盖和内部 Overdraw，不能叫作“只改变顶点数”。

大尺寸 Box 到 15% Box 的约束更强：生成逻辑围绕原 Bounds 中心把顶点三轴缩到 15%，保留 UV、法线、切线、索引、SubMesh、材质、实例布局与逐株光照，并恢复大 Box 的保守剔除 Bounds；两个构建摘要的光照签名一致，15% 摘要还保存了实例布局签名。但它们仍是不同 APK、不同采样时段。两个 APK 的体积分别为 `270621866` 与 `186428728` 字节，相差 `84193138` 字节，即相对大尺寸 Box APK 减少 `31.111%`，这一跨构建漂移没有被解释，故：

- 各自测试构建内的 BRG→GO→BRG 顺序窗口可按各自会话证据使用；
- 跨真实草、大 Box、15% Box 的比较只作为相关性证据；
- 不能把跨包差异称为严格单变量证明。

三段会话连续性也不能统一处理：15% Box 保存了同一目标 PID；大 Box 与高密度真实草具有同一应用会话说明和连续时间窗，但没有 PID；稀疏组只有顺序时间窗、状态截图和操作者切换说明，没有明确同会话或同 PID 字段。四组都缺少自动化模式切换事件日志。几何变体之间则明确是三个独立 APK，不是一个进程里切换 Mesh。

#### 四、如何解释 CPU、GPU、Overdraw 与内存

**GPU。** 高密度真实草三段约 20 FPS，历史 `GPU %` 字段约 99%；在其字段精确定义未保存的前提下，这一组合与 GPU 饱和及几何/覆盖主导一致，但不能提升为“GPU 已被独立证明是主要瓶颈”。8192 株 × 704 三角形约为 576.7 万个实例三角形，双眼、Cull Off、Alpha Clip 和遮挡层叠还会增加工作量。跨构建对照同样只支持“真实草几何与覆盖的组合成本重要”，不能拆分顶点、三角形、Alpha Clip 和片元各自占比。

**CPU。** 大尺寸 Box 与 15% Box 中，普通 GO 段的历史 `CPU %` 和 `CPU+GPU ms` 字段均高于两段 BRG，回切后恢复，这与普通 GO 完整对象路径具有更高 CPU 侧总压力一致。由于百分比定义、线程分项和窗口聚合方法均未保存，不能把差值唯一归因于主线程、渲染线程、Renderer、LOD、动态探针绑定或 Draw 提交中的任何一项。

**Overdraw。** Alpha Clip 植被通常在不透明队列绘制，所以会出现在 Opaque Overdraw 视图中；Transparent Overdraw 没有颜色不代表没有重复片元成本。Cull Off、草叶交叉、密集实例、较大屏幕尺寸和双眼都会增加工作量。现有证据只记录 BRG 侧一个植被 `BatchDrawCommand`，没有普通 GO 侧可比计数，因而不能声称 BRG 减少了提交命令；无论提交如何组织，BRG 本身都不会自动消除已经进入视野的几何或片元成本。

**Stale。** 按表前给出的操作性解释，高密度真实草约 `72 Stale/s` 与约 20 FPS 同时出现，说明应用明显无法持续提供 90 Hz 所需的新帧。由于未保存逐样本序列和供应方精确定义，本文不再把该字段用于更细的原因拆解。

**内存。** 普通 GO 段相对初始 BRG 的 Total PSS 分别增加约 `75.473 / 45.568 / 66.998 / 40.193 MiB`（稀疏、真实草、大 Box、15% Box），由 KB 差值除以 1024 得到。PSS 覆盖 Unity、XR、代码、纹理、图形资源和分配器保留，不能全部归因于 GameObject，也不能仅凭回切残留判断泄漏。

#### 五、BRG、普通 GO 与 SH 的实际差异

四组性能 APK 中：

- **BRG** 使用 `StaticLightColor`。刷新阶段在每株 `VisualRootSpaceBounds.center` 取得完整 L2 探针，以实例局部向上方向求出最终 RGB，并写入 SceneAsset/Heap；运行时直接读取最终颜色。
- **普通 GO** 从同一 SceneAsset 的实例变换展开 GameObject、Transform、MeshRenderer 与 LODGroup，材质启用 Unity GPU Instancing；Unity BlendProbes 按位置取得探针。Bakery 的非 Lightmap Shader 路径消费 `unity_SHAr/Ag/Ab` 的 L0/L1 表示，并按顶点法线执行 Geomerics 重建。

稀疏组的设备材料直接记录了上述 BRG/GO 光照代码路径；但该组没有保存场景灯、探针布置、Eye Buffer、质量档等配置，所以不能把其画面或性能差异进一步归因到具体光照配置。

因此，“探针烘焙模式为 Bakery L2”不等于两条运行时路径都在 GPU 上完整评估 L2。BRG 的完整 L2 已在刷新阶段求成最终 RGB；普通 GO 运行时使用 Ar/Ag/Ab 表示。两侧颜色和运行成本都不是严格等价。

#### 六、当前实现与历史设备数据的边界

当前 BRG 已改用新的 32 B 逐株 ABI、光照记录和运行时组织；该 ABI 的现有 Editor 证据绑定到 Unity `2022.3.62f3`、Direct3D11 和 Unity.Mathematics `1.3.2`。历史性能 APK 使用旧版逐株最终颜色路径，两者不是同一协议，`StaticBakerySh` 也没有进入四组设备实验。当前光照生成与消费见[Bakery L2 静态光照与投影代理](./unity-vegetation-bakery-static-lighting-pipeline.md)，逐株协议见[BRG 逐株 Buffer 的 32 字节压缩与量化 ABI](./unity-brg-packed-instance-buffer-quantization.md)。

因此，旧 APK 的 FPS、PSS、CPU/GPU 利用率只能描述本文冻结的历史系统；Editor 中的 Buffer 字节变化也不能替代当前实现的 Quest Vulkan 帧时、带宽、ALU、物理显存、功耗或热稳定性 A/B。

#### 七、把历史观察升级为当前结论的重测协议

要把历史趋势升级为当前结论，应在同一 APK 中完成自动化 A/B/A，并冻结下列条件：

1. **同一输入。** 固定设备系统、刷新率、质量档、Eye Buffer、场景、实例布局、Mesh、Material、LOD、灯光、Probe 和相机轨迹；保存对应内容摘要。
2. **同一会话。** 自动记录 PID、构建标识、模式切换事件、预热区间、采样起止、CPU/GPU 档位、频率、温度和电量；A、B、回切 A 使用同一进程。
3. **同一可见工作量。** 每个采样窗口记录 Active 区域、Frustum Candidates、Visible After LOD、三角形/顶点、Draw Command 和实际屏幕覆盖；不能用 Editor 默认姿态代替设备计数。
4. **区分两类问题。** “完整 BRG 系统对普通 GO 系统”保留各自真实光照和对象生命周期；“只比较提交路径”则必须让几何、材质、光照计算、剔除结果和可见实例完全相同，并通过冻结截图或预先定义的图像、实例与光照误差阈值确认功能等价。两类结果不能混写。
5. **同包切换几何。** 几何或覆盖实验应在同一包、同一场景中切换已冻结 Mesh，避免 APK 体积、资源剥离和采样时段成为跨包混杂。
6. **保存可分解指标。** 除 VrApi 窗口值外，记录原始字段名、字段单位、CPU 百分比归一化定义、窗口聚合方法，以及主线程、渲染线程、GPU Frame Time、Overdraw、PSS 分类和原始逐样本序列。
7. **平衡顺序并重复。** 预先规定冷却、预热、稳态判定、异常值、置信区间与效应量口径；跨会话重复多轮，并交替执行 A/B/A 与 B/A/B，报告顺序效应和回切恢复程度。

只有上述协议中的一个变量组发生预先声明的变化，才能把差异提升为对应机制的因果证据；否则仍应按完整系统相关性解释。

#### 八、适用边界

- **设备与场景**：数值只代表 Quest 3S 及本文列出的模型、场地、相机、刷新率、密度和历史光照条件；稀疏组缺少设备可见数及部分配置。
- **可见性**：Box 的“全部入画”来自头显观察和截图，不是程序化机器计数；15% Box 的不交叠门禁不含 Shader 顶点位移。
- **会话**：只有 15% Box 留有同 PID；其它组的连续性证据较弱，且头显姿态与预热时长未程序化锁定。
- **跨包**：大 Box 与 15% Box 存在 31.111% APK 体积漂移，跨几何变体只能作相关性证据。
- **路径差异**：BRG 与普通 GO 的光照和对象生命周期不同，本文是完整系统路径对比；`CPU %`、`GPU %` 和 `CPU+GPU ms` 的精确定义、归一化与线程分项均未保存。
- **时代边界**：这些历史实机数据不验证当前 ABI、Shader、光照布局或运行时组织；Unity 2022.3.62f3 + Direct3D11 + Unity.Mathematics 1.3.2 是当前 ABI 的 Editor 证据组合，不是本文历史 Quest APK 的设备验证。

#### 九、结论

四组历史 Quest 3S A/B/A 说明：在本文冻结的完整系统路径中，Box 组的普通 GO 段与更高 CPU 侧总压力一致；高密度真实草约 20 FPS 与历史 `GPU %` 约 99% 的组合，与 GPU 饱和及几何/覆盖主导一致；BRG 不会自动消除已经可见的几何、Alpha Clip 或 Overdraw 成本。

这些数据不能证明 BRG 相对 GO 减少了提交命令，因为只记录了 BRG 侧一个植被 `BatchDrawCommand`，没有 GO 侧可比计数；也不能把跨 APK 的网格变化称为严格单变量实验。历史指标定义、会话连续性和当前协议身份都不完整，因此本文可作为历史相关性证据和重测设计依据，不能作为当前 32 B ABI 的 Quest 性能结论。当前决策必须按第七节协议在同一 APK、同一进程和冻结工作量下重新采集。
