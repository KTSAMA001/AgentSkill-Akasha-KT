# 使用示例

> 本文件只演示典型场景，不另行定义规则。发生差异时，以 `SKILL.md`、对应 workflow、记录模板、reviews 与 scripts 说明为准。

## 写入类示例的共同收尾

下文写入或修正示例提到“完成记录闭环”时，指：

1. 按授权检查仓库、分支、远端和工作树；发布任务在写入前安全同步，冲突时停止。
2. 完成重复、正确性、时效、来源与脱敏检查，向用户预览并确认。
3. 按模板形成正式候选与本地资源，不写占位草稿。
4. 运行首轮结构校验。
5. 对最终候选完成无历史只读冷读，并保存绑定记录及资源 SHA-256 的完整证据。
6. 运行“校验 → 重建 INDEX 文件清单 → 再校验”，有新标签时同步标签注册表。
7. 只有得到相应授权时，精确暂存本次文件、提交并推送；不使用宽泛暂存，不夹带已有改动。

## 一、查找已有经验

### 示例 1：本地命中

**用户**：“之前有没有记录过 Unity 协程怎样等待一帧？”

**操作**：

1. 读取 [search.md](./workflows/search.md)。
2. 只在 `../data/*.md` 中按“协程”“yield”等关键词、标签和文件名检索。
3. 读取命中正文，检查状态与适用版本。
4. 说明这是阿卡西本地记录，并给出结论、限制和记录文件；不联网、不写库。

### 示例 2：本地未命中后继续外部调研

**用户**：“帮我查下最新 Unity DOTS 的 IJobEntity 用法，本地没有就继续查官方资料。”

**操作**：

1. 先只检索 `../data/*.md`。
2. 未命中时明确说“阿卡西本地未命中”。
3. 因用户已要求继续调研，查 Unity 官方文档等一手来源。
4. 将结果标为外部调研结论，不说成库存知识。
5. 若值得记录，先询问用户；未获确认不写入。

若用户只问“以前是否记录过”，步骤 2 后就结束，不自动联网。

## 二、记录新经验

### 示例 3：记录协程排障

**用户**：“把刚才解决的 Unity 协程问题记一下。”

**操作**：

1. 读取 [record.md](./workflows/record.md)，检索重复记录并核对事实。
2. 预览：标题、概要、`#unity #experience` 等标签、来源、脱敏结果和 `../data/unity-coroutine-yield-return-null.md`。
3. 用户确认后，写成“场景与症状 → 根因 → 方案为何有效 → 验证与边界 → 可复用结论”的正式文章。
4. 完成记录闭环；最后按真实情况报告“仅本地写入”“本地已提交”或“已推送并核对”。

## 三、更新已有经验

### 示例 4：补充版本注意事项

**用户**：“刚才那条协程记录还要补充 Unity 2022 的注意点。”

**操作**：

1. 读取 [validate.md](./workflows/validate.md)，定位记录并核对新信息。
2. 更新正文、更新日期和验证记录；状态或标签变化时同步索引层。
3. 因版本说明改变读者行动，不把它当机械修正；对最终候选重新完整冷读。
4. 完成记录闭环，只处理该记录及其直接依赖文件。

## 四、大型架构文档

### 示例 5：保存 VR 变体收集器架构

**用户**：“把这个 VR 变体收集器的完整设计保存下来。”

**操作**：

1. 检查已有主题、来源和敏感项目细节，预览并等待确认。
2. 新建 `../data/vr-variant-collector-architecture.md`。
3. 按知识博客或技术论文质量写清目标与约束、端到端数据路径、组件责任、打包策略、兼容关系、失败恢复、迁移顺序、代价和证据边界。
4. 如确有帮助，在相关记录中加入 `./vr-variant-collector-architecture.md`，但当前正文不能依赖该链接才成立。
5. 完成记录闭环；冷读重点检查没有项目背景的领域读者能否复述机制和采用条件。

## 五、错误或过时记录

### 示例 6：WWW 类已过时

**用户**：“这条 WWW 类用法是不是已经过时了？”

**操作**：

1. 读取 [validate.md](./workflows/validate.md)，定位记录并核对当前 Unity 官方资料与适用版本。
2. 若证据确认过时，更新为 `📕 已过时`，说明影响版本、风险和 `UnityWebRequest` 替代路径；必要时折叠保留历史方案。
3. 更新日期和验证记录，对实质改写后的候选重新冷读。
4. 完成记录闭环。证据不足时改为待验证并说明缺口，不强行宣告废弃。

## 六、经验冲突

### 示例 7：async/await 与协程

**用户**：“两条记录一个推荐 async/await，一个推荐协程，哪个对？”

**操作**：

1. 先按 [search.md](./workflows/search.md) 读取两条记录及其状态、版本和场景。
2. 若差异来自适用场景，分别说明：纯计算、文件或网络 IO 与 Unity 帧生命周期需求并不相同。
3. 用户只问结论时保持只读；用户要求修正时才进入验证流程。
4. 修正时在两篇正文中明确条件并相互引用，再对所有实质改写候选分别冷读和完成收尾。

## 七、用户反馈验证失败

### 示例 8：实践结果与记录不一致

**用户**：“你之前那条协程写法在我的版本里报错。”

**操作**：

1. 收集最小错误信息、Unity 版本和复现条件，定位原记录。
2. 对照官方资料和最小复现，判断是事实错误、版本差异还是环境差异。
3. 事实错误就修正方案和状态；版本差异则保留两种边界；证据不足则标注待验证。
4. 更新验证记录，重新冷读实质改写，并完成结构、索引及授权范围内的发布步骤。

## 八、公开文章完整离线保存

### 示例 9：保存带图技术博客

**用户**：“把这篇公开博客完整离线保存到阿卡西。”

**操作**：

1. 读取 [record.md](./workflows/record.md) 的“学习用途本地留档”分支，确认可访问范围和目标文件。
2. 抓取并逐项检查标题层级、正文开头和结尾、段落、表格、代码、引用与内容图片；被截断或缺资源时不能声称完整。
3. 将内容图片按顺序保存到 `../assets/<record-name>/`，正文替换为本地相对路径；不保存头像、广告和装饰图。
4. 在标准元数据和概要之后，于 `### 内容` 下按原顺序完整转录，不改写、缩写、省略或把作者分析插入原文。
5. 冷读只审核本地包装、导航、来源与资源完整性，不按意见篡改外部原文。
6. 完成记录闭环；来源 URL 和来源日期必须保留。

## 九、系统规则变更

### 示例 10：优化 Skill 流程

**用户**：“在功能不变的前提下整理阿卡西 Skill。”

**操作**：

1. 读取 [governance.md](./workflows/governance.md)，从未改动基线盘点全部能力和消费者。
2. 冻结 `data/**`、`assets/**`、历史审核证据和未授权索引内容，只在隔离候选中调整系统文档。
3. 检查四类意图、离线归档、冷读、模板、索引、标签、脚本和 Git 发布能力逐项仍有去向。
4. 运行脚本、链接、场景和独立只读复审；没有提交或推送授权时，只保留本地未暂存改动并如实报告。
