### 完整复述

本文解决的是按运行时 Cell 隔离的解析查询扩展问题。每个 Cell 有一份 QueryWorld，内部包含多个 Heap；Heap 是逻辑分组而非内存堆，每个 Heap 又包含 Sphere、Capsule、Box Shape。查询不依赖 Unity Collider 是否激活，而是通过数学窄相位完成 Raycast、OverlapCapsule、SweepCapsule；BVH 只负责宽相位候选筛选。

索引采用两级混合策略：

- Heap 数或单 Heap 的 Shape 数少于 64 时线性扫描。
- 达到 64 时，不在注册阶段立即建树，而在首次真正查询时懒建。
- 顶层 BVH 筛 Heap，候选 Heap 内的第二层 BVH 再筛 Shape。
- 节点保存合并 AABB、Purpose OR、连续元素区间和子节点索引；叶容量为 8。
- 构建先按稳定身份消除字典顺序影响，再按中心最长轴做确定性中位数切分。由于每层递归都对子区间重新排序，文中正确地把上界写为 `O(n log² n)`，没有误写成一次预排序实现的 `O(n log n)`。
- 新增、替换或移除 Heap 会使顶层派生索引失效；替换会重建该 Heap 的 Shape 缓存与懒建容器，其余 Heap 的 Shape 树可以保留。
- 位置、尺寸、类型或 Purpose 的普通变化必须按 Heap 替换处理；统一 Rebase 是例外，它把同一个 `-delta` 应用于权威数据、缓存 AABB 和已建节点，不改变树拓扑。
- 构建异常后的局部发布、线性回退和失败世代抑制重复冷建，被明确标为生产接入建议而非已经验证的能力。

查询链交代完整：

- Raycast 依次筛 Heap AABB、Shape AABB，再对 Sphere/Capsule/OBB 做解析射线测试，并用距离和稳定身份收尾。
- OverlapCapsule 先生成查询 AABB，经过两级索引及补充粗筛，再做解析接触；单 Cell 内按 StableGuid 去重排序，跨 Cell 必须使用 `(RuntimeCellIdentity, StableGuid)`，因为 StableGuid 不保证跨运行时 Cell 全局唯一。
- SweepCapsule 对不旋转的线性平移使用起终点胶囊 AABB 并集；若中途旋转，必须另建覆盖中间姿态的保守 Bounds。候选窄相位最多执行 64 次保守推进。
- 文中还指出同一实例多 Shape 时，线性和 BVH 候选顺序差异可能改变接触点、法线或 ShapeType；需要接触细节的玩法应增加 ShapeId 或显式优先级。

复杂度和内存边界也能独立理解：

- 注册 Shape 缓存为 `O(S_i)`，顶层稳定排序为 `O(H log H)`，单树构建为 `O(n log² n)`，常驻节点、索引和遍历栈为 `O(n)`。
- 预热、良好分布、局部稀疏时，树路径描述为顶层 `O(log H + K_H)`、Shape 层 `O(log S_i + K_i)`；全覆盖、高重叠、同中心、巨型 Bounds、长 Ray/Sweep 仍会退化到 `O(H + S)`。
- Overlap 另有 `O(R log R)` 排序；Rebase 为 `O(H + S)`。
- 复用 List、HashSet、栈会保留历史最大容量；“零托管分配”只覆盖容量稳定的特定热路径，不能外推到冷建、重建或多命中。

正确性核心前提表达得非常明确：查询自身 Bounds、Shape AABB、Heap Bounds 必须逐层保守包含。当前参考实现用排除碰撞体的视觉 Bounds 注册 Query Heap Bounds，外伸 Shape 会在顶层产生确定性假阴性。文中给出的修复方向是分离 Visual/Query Bounds，或注册时直接聚合全部 Shape Bounds，并要求同时覆盖线性与 BVH 阈值路径。

多 Cell 和 Floating Origin 的边界清楚：每个 Cell 独立拥有索引和容器，整世界查询仍需外层逐 Cell 调度或另建世界级索引；单 Cell 数据不能外推为整世界性能。Rebase 的局部平移能力也不等于渲染、解析查询、PhysX 已经原子接通。
