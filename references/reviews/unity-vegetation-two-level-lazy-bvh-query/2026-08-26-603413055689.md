## 独立主题复述

本文讲解一种面向 Unity 大规模静态或低频变更解析碰撞数据的两级宽相索引：

- 每个运行时 Cell 独立维护 QueryWorld。
- 顶层 BVH 筛选 Heap，候选 Heap 内的第二层 BVH 再筛 Shape。
- 小于阈值的集合保持线性扫描，大集合在首次需要时懒建 BVH。
- BVH 只生成候选，Sphere、Capsule、OBB 的解析窄相负责确定真实命中。
- Heap 增删或替换使顶层派生索引失效；Cell 卸载释放整份查询世界；Floating Origin 通过平移缓存和节点维持拓扑。

适用范围是 Unity 2022.3 LTS 中静态或低频替换的 AABB 宽相位，以及 Ray、OverlapCapsule、固定姿态线性 SweepCapsule 对 Sphere、Capsule、Box 的查询。

本文明确不负责：

- ConvexMesh、PhysX 接触与触发器语义；
- Collider Proxy 的流送或可见性；
- 并发查询和索引修改；
- 跨 Cell 的世界级索引与统一调度；
- 旋转 Sweep 的完整算法；
- Quest、ARM、IL2CPP 或完整生产系统性能保证；
- 在 Query Heap Bounds 包含性尚未修复时直接给出生产可用结论。

具备 Unity、AABB、BVH 和基础复杂度知识的目标读者可以单篇理解设计主线、生命周期、正确性前提与证据边界。`Heap`、`QueryWorld`、`ColliderStreamer` 等术语略带实现色彩，但不依赖特定项目历史才能理解。

## 内部一致性与证据边界

- Heap 注册时缓存 Shape AABB 和 Purpose，Shape 树按候选需求懒建；顶层 Heap 树在 Heap 数达到阈值后首次查询时懒建。新增、替换、移除使顶层失效，而未变化 Heap 的 Shape 树可以保留，逻辑一致。
- 删除 Heap 会释放其缓存和派生索引，Cell 卸载释放整个 QueryWorld。替换旧 Shape 索引的释放或回收是隐含语义，建议进一步写明，但不造成现有论述矛盾。
- 顶层和 Shape 层均通过 AABB 与 Purpose OR 剪枝，最终命中交给解析窄相；Collider 流送不参与候选生成，职责分离明确。
- 多 Heap 通过顶层索引参与；多 Cell 则由外层逐 Cell 调度，不共享世界级 BVH。单 Cell 微基准不能消除多 Cell 的调度、内存和冷建成本，文内已明确限制。
- Rebase 对权威几何、缓存 AABB 和已建节点作相同刚性平移，未建树随后从新坐标构建，拓扑保持结论成立。实际实现还应确保顶层连续元素副本等所有 Bounds 持有者同时更新。
- `O(n log² n)` 构建上界与“每层重新排序子区间”的算法相符。查询复杂度只在良好分布、预热和局部稀疏条件下写为 `O(log n + K)`，并保留 `O(H+S)` 最坏情况；Overlap 排序、Sweep 迭代和 Rebase 成本也分别计入，内部一致。
- 内存部分正确区分了常驻 `O(n)`、历史最大容量复用与冷建临时峰值；“稳态 0 B”没有被外推到冷建、重建或容器扩容。
- 正确性链完整写出查询范围、Shape AABB、Heap Bounds 三层保守包含关系，并指出任意一层偏小都会在窄相前产生假阴性。
- 固定姿态线性 Sweep 使用起终 AABB 并集是保守的；允许旋转时必须覆盖中间姿态，前提清楚。
- 非有限输入、擦边容差、极端坐标、重复 Rebase 和线程串行所有权均有说明。
- 稳定结果没有被过度承诺：文中明确指出 StableGuid 无法稳定选择同一实例的多个 Shape，并建议增加 ShapeId 或显式优先级。
- 性能倍率可由 `1,391,980 / 25,223` 复算为约 `55.1869`。但实验本身缺少 CPU、计时频率、独立重复、方差、分位数、随机交错顺序和完整夹具代码，无法独立复现实验值。正文已经明确列出这些缺口，并把结论限制在一次预热、理想、稀疏的单层 AABB 观测，没有推广到完整两级查询、冷建、多 Cell 或目标设备。
- “显著避开全量扫描”可由该次约 55 倍观测支持为工程描述，但不应理解为统计显著性；正文的限定语基本压住了这一风险。
