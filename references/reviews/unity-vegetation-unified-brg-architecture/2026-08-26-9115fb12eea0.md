系统复述：

- 数据权威链清楚：普通 Prefab 是烘焙输入；`PrototypeAsset` 保存带 `PrototypeGuid` 的静态绘制、LOD、边界及显式碰撞描述；`SceneAsset.PrototypeTable` 建立 `PrototypeId` 映射，场景实例只保存 `PrototypeId`、`StableGuid` 与 Heap 局部 TRS。运行时集中提交 BRG，不实例化逐株 Prefab。Prefab、Prototype、SceneAsset 不是三个并列权威源。
- 术语边界清楚：历史正文中的普通 `Cell` 对应当前实现的内部空间块 `Heap`；“运行时 Cell”则是“管理器组件＋一份 SceneAsset＋一套独立运行资源”的加载与所有权域。每个运行时 Cell 独立拥有 BRG、Raw Buffer、剔除快照、HeapMask、QueryWorld 和 ColliderStreamer。
- 身份与地址链清楚：`SceneGuid` 标识 SceneAsset；`HeapGuid` 由 `SceneGuid + HeapCoordinate` 确定性生成；`StableGuid` 是资产内持久实例身份，跨 Heap 移动保留；`RuntimeIndex` 是 Compile 后的 Heap 内连续临时索引；加载时按 SceneAsset 当前 Heap 顺序形成 `HeapBase`，并得到 `GPU Slot = HeapBase + RuntimeIndex`。当前单 Batch 下，`GlobalInstanceIndex`、`GPU Slot` 与 `BatchLocalIndex` 数值相同，但不应被当成持久身份。
- 当前流水线完整串联为：Painter 提交运行时 Cell 局部坐标 → Commit 创建或更新 Heap → 保存 StableGuid、PrototypeId、局部 TRS → Compile 按 PrototypeId、Morton、StableGuid 排序并生成 RuntimeIndex、Bounds、光照表与 Hash → 加载独立 BRG、Buffer、剔除和物理资源 → 一次上传该运行时 Cell 的全部 Heap 与实例 → HeapMask 控制粗筛 → 全实例 Count → LOD/RenderBucket → Prefix → 全实例 Scatter → `visibleInstances` 与 DrawCommand。
- HeapMask 闭环足以让陌生读者直接理解：
  - 索引：每个已加载运行时 Cell 独有一份掩码，以 SceneAsset 当前 Heap 顺序索引，每 Heap 一字节。
  - 更新者：管理器把 Heap Bounds 变换到世界空间，再依据兴趣源距离和加载/卸载迟滞更新；`VegetationBrgWorld` 写入新掩码前等待既有剔除 Job。
