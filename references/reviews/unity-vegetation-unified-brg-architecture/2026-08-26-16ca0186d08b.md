系统复述：

1. 作者数据链

```text
普通 Prefab
  → 在隔离的 Prefab Contents 中读取 Authoring / LOD / Renderer / 显式碰撞标记
  → 烘焙为 PrototypeAsset，以 PrototypeGuid 标识
  → SceneAsset.PrototypeTable 建立 PrototypeId 映射
  → 实例仅保存 PrototypeId + StableGuid + Heap 局部 TRS
```

Prefab 是烘焙输入，不是运行时逐株权威；`PrototypeAsset` 保存静态绘制、LOD、碰撞描述，不拥有场景位置；`SceneAsset` 才是场景实例作者数据权威。运行时集中提交 BRG，不实例化每株原始 Prefab。

2. 运行时层级、身份与地址

参考实现中的“运行时 Cell”是“管理器组件 + 一份 SceneAsset + 一整套独立运行资源”；资产内部的最小空间块叫 Heap。正文后续的通用 Cell 映射到该 Heap，不能与运行时 Cell 混称。

```text
运行时 Cell
  ├─ SceneAsset
  ├─ 多个 Heap
  ├─ 独立 BRG / Raw Buffer / Snapshot / HeapMask
  ├─ 独立 QueryWorld
  └─ 独立 ColliderStreamer
```

当前连续寻址链为：

```text
HeapCoordinate = floor((cellLocalPosition - partitionOrigin) / heapSize)
HeapGuid        = Deterministic(SceneGuid, HeapCoordinate)

Compiler：
  Heap 内按 PrototypeId → Morton → StableGuid 排序
  → 分配连续 RuntimeIndex

加载：
  HeapBase = 当前 Heap 之前全部 Heap 的实例数
  GPU Slot = HeapBase + RuntimeIndex
  GlobalInstanceIndex = GPU Slot
  当前单 Batch下 BatchLocalIndex = GPU Slot
```

`StableGuid` 是资产内持久身份；`RuntimeIndex`、`HeapBase`、GPU Slot 和 BatchLocalIndex 都是派生地址，不得用于存档或跨编译身份。目标架构还定义了 `AssetPersistentId + InstanceStableId`、PageID/LocalSlot、RenderBucketKey 与 BatchRegistrationPolicy，但跨资产世界命名空间、Buffer Page 和多 Batch 尚未实现。

3. Painter、Buffer、剔除与卸载完整链

```text
Painter 取得一个运行时 Cell 的作者 Authority
  → Stage / Preview 仅形成内存候选或预览矩阵
  → Commit 创建或更新 Heap，保存 StableGuid、PrototypeId、Heap 局部 TRS
  → Compile 受影响 Heap，生成排序、RuntimeIndex、Bounds、光照表、Hash
  → 加载整个运行时 Cell
  → 创建独立 BRG / Buffer / Snapshot / QueryWorld / ColliderStreamer
  → 按 Heap 顺序派生 HeapBase 和 GPU Slot
  → 整 Cell 一次上传量化后的 32 B 逐株记录
  → 兴趣源与迟滞更新该 Cell 的 HeapMask
  → 每视图：Heap 粗筛 → 全实例 Count → LOD/RenderBucket → Prefix → 全实例 Scatter
  → 生成 visibleInstances 与 DrawCommand
```

`HeapMask` 是按 SceneAsset 当前 Heap 顺序索引的一字节掩码。它只门禁本次剔除是否继续处理 Heap，不代表 Heap Loaded/Unloaded，也不上传、缩容或释放 Heap Buffer。Count/Scatter 仍按本运行时 Cell 全实例长度调度，复杂度近似：

```text
O(运行时 Cell 总实例数 × Camera/Light 视图数)
```

因此增量边界是：作者 Commit/Compile 可限定到受影响 Heap，HeapMask 是小型增量更新，变换预览可原地修补；但初次加载、Rebase 和 Cell Transform 更新仍重建整 Cell Snapshot 并全量重编码、上传 32 B 实例区。当前没有紧凑实例工作集、Heap 级 GPU 流式卸载或 Buffer Page。

整运行时 Cell 卸载时，渲染侧先排空覆盖既有剔除链的最终 CPU JobHandle，再移除 BRG 可回调状态，释放 NativeArray、Prototype 引用、Batch 和 GraphicsBuffer；物理侧另行反注册 Heap、归还代理并释放 QueryWorld；SceneAsset、Mesh、Material 的最终卸载由外层场景或资源句柄负责。此链有 CPU Job 屏障，但没有显式 GPU Fence 或异步 Retiring 世代证据。

4. 32 B ABI 与 128 B 辨析

```text
N = 实例数
H = Heap 数
C = StaticLightColor 记录数
S = StaticBakerySh 记录数

bytes = Align16(
          Align16(96 + 32×max(1,N) + 128×max(1,H) + 8×max(1,C))
          + 20×max(1,S))
```

- `32 B × N`：2026-08-26 候选的固定逐株记录。
- `128 B × H`：每 Heap 的两类光照量化参数，不是逐株记录。
- “由 128 B 收敛到 32 B”描述旧逐株 ABI 到候选逐株 ABI 的变化。
- `96 B`：64 B 合法零地址哨兵及两组 16 B Cell 风场参数。
- `8 B`、`20 B`：两种稀疏光照记录。

所以文中不存在实际的 128 B/32 B 口径冲突，只存在两个不同维度都使用了“128 B”；上下文已经能区分。32 B 编码要求最终矩阵有限、无剪切、非镜像且为正数统一缩放；CPU 剔除使用相同量化后 TRS，并保守扩张风摆 Bounds。

5. Rebase 与 Cell Transform

核心坐标公式完整且符号一致：

```text
renderMatrix =
    Translate(-absoluteOriginOffset)
    × CellTransform.LocalToWorld
    × authoredCellLocalTRS
```

Rebase 接收新的累计绝对 `absoluteOriginOffset`；物理侧接收本次变化量 `delta`，QueryWorld 的 Heap/Shape 广相位、ColliderStreamer 的缓存描述和现存代理都平移 `-delta`。

Rebase 不重新分桶、不重建 Heap、不改写 SceneAsset。以下内容保持不变：

- Heap 局部 TRS
- HeapCoordinate、HeapGuid
- StableGuid
- Compile 排序与 RuntimeIndex
- 当前 Heap 顺序不变时的 HeapBase/GPU Slot

变化的是实例世界矩阵、Heap Bounds、风场空间原点、查询 Shape 和 PhysX 代理的当前世界坐标。每次都从权威高精度局部 TRS 重新编码，不累计使用上一次的 32 B 量化结果。

渲染侧发布顺序为：

```text
新 absoluteOriginOffset
  → 拒绝 NaN / Infinity
  → 互斥并完成上一条剔除 Job，保存 HeapMask
  → 旧 CellTransform + 新 absoluteOriginOffset 构建候选 CPU Snapshot
  → 从权威局部 TRS 全量编码、上传候选 32 B Buffer，并更新风场参数
  → 前两步成功后清理旧预览
  → 发布 SceneBatch Origin、StableGuid→Slot 反查及公开 Snapshot
  → World 发布同一 Origin
  → 重建 Persistent NativeArray
  → 按原索引恢复 HeapMask
```

未加载 Cell 只缓存绝对偏移，后续建批时使用。Half 上溢、最终统一缩放下溢或非有限 Origin 会在相关字段发布前失败；现有回归证明这些输入下旧 Origin、CellTransform、公开 Snapshot、完整 Buffer 和预览保持不变。未证明 Persistent NativeArray 后续分配失败可原子回滚，也未证明 GPU 在途读取已经由 Fence 或世代 Buffer 退役。

Cell Transform 更新不是 Rebase：管理器每帧读取有限、无剪切、非镜像、正统一缩放的新 Transform，并以“新 CellTransform + 现有绝对 Origin”走同一候选 Snapshot、全量 Buffer 上传和成功后发布链。它同样不改变作者分桶或身份，但会改变最终世界 TRS、Bounds、风摆距离和量化值。

Rebase 链已经补全，同时准确保留了协调缺口：当前只有渲染绝对 Origin、QueryWorld 增量和平移 Collider 代理三个局部入口，尚无内建的全局 Floating Origin 协调器。生产接入方必须按同一世代向全部已加载运行时 Cell 分发绝对 Origin 与物理 delta；现有证据不证明渲染、QueryWorld、PhysX 三者的跨系统原子失败恢复。文中没有把该协调器误写为已实现。

7. 当前实现与目标契约

当前实现是每运行时 Cell 独立资源、单 Buffer、单 Batch、全 Cell 上传、HeapMask 门禁和全实例 Count/Scatter；普通多相机仍共享 `PreviousLod`，主相机与显式参考物体决定激活集合；预览和卸载主要依靠 CPU 同步。

目标契约包括 Buffer Page、多 Batch、异步实例流式加载、Desired/Loaded/Active 三态及 Loaded 就绪屏障、紧凑工作集、每视图 LOD 历史与淘汰、会话世代、跨资产世界命名空间、全局多 Cell 预算、Running→Closing→Freeze→Drain→Disposed、热切换 Retiring，以及带 CPU/GPU/命令世代和 GPU 退役屏障的 `PreviewPublication`。记录持续用“部分覆盖”“未覆盖”“应/推荐”区分目标与现状，没有把目标架构写成现成功能。
