## 内部一致性与证据边界

- 资产权威一致：作者数据、派生缓存、运行快照和预览覆盖严格分层；缓存、快照和预览均未被赋予第二权威源地位。
- 地址链完整：`StableID → LogicalIndex → PageID + LocalSlot` 与绘制分类分开；随后落到 `BatchID + BatchLocalIndex`。正文也明确区分 `visibleInstances` 的区间位置和数组元素值，DrawCommand 的 offset/count 语义清楚。
- 会话所有权一致：共享后端协议与共享会话被明确区分；多 Scene、多运行时 Cell及 Preview Scene 可以隔离建会话，但实例集合和提交范围不得重叠。
- ActiveHeapSet 定义充分：`Desired`、`Loaded`、`Active` 三态分离，Loaded 发布要求 CPU、依赖资源、GPU 数据和 Batch 注册同时就绪。
- 激活与卸载没有混淆：激活可以只是改变候选集合；真实分片卸载则必须经历门控、CPU 排空和 GPU 退役。全文也明确禁止把驻留数据加掩码描述为异步流送。
- 多视图边界清楚：各视图独立剔除，LOD 历史需要稳定视图身份隔离；收到多个回调不被当作隔离已实现的证据。
- Count/Prefix/Scatter 关系正确：分组键、互斥区间、写入值和 DrawCommand 引用顺序一致。
- CPU/GPU 生命周期没有混淆：`Draining` 等待 CPU Job，`Retiring` 处理 GPU Fence或独立资源世代；CPU 完成不被错误等同于 GPU 已停止访问。
- 热切换与完整关闭一致：完整会话使用 `Running → Closing → Draining → Retiring → Disposed`；热切换保持会话 Running，只让旧快照世代单独排空和退役。
- 事实强度克制：正文主要表达架构不变量、设计目标、可选政策和验收方法，没有伪装成当前项目实现。验证表明确声明未实际执行；分页、多 Batch、紧凑工作集、多视图历史和 GPU 退役仍列为待验证。
