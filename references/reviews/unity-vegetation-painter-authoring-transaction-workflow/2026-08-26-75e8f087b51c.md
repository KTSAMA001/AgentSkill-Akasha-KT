系统复述

- 系统明确分离源 Prefab、Prototype 资产、运行时 Cell 与 Painter。SceneAsset 是单个运行时 Cell 的作者数据权威；Heap 是其内部空间分区，不是独立资产或独立 BRG Batch。
- 主闭环清晰：
  `Authority → HeapStage/目标快照 → 模式对应的 Preview → Commit → Compile → Save → PublishNotification`。
  Commit 只把作者数据写入内存中的序列化 SceneAsset、登记完整资产 Undo、增删 Heap 并标脏；Compile 生成排序、RuntimeIndex、Bounds、光照表和 Hash；Save 才持久化整份资产；PublishNotification 只通知宿主从已保存正式资产刷新 BRG，不复制作者数据。
- Preview 没有被笼统宣称为最终结果：
  Paint/Erase 只反馈笔刷范围或候选；Replace/Reproject 只反馈选择目标；只有 Transform 用临时矩阵和 CPU Bounds 补丁提供结果预览。
- Prototype 创建/刷新采用分段门禁：
  `PrepareSourceInput → ValidateInput → SaveSourcePrefab → BuildCandidate → ValidateCandidate → Promote/ReplaceFile → RefreshReferencedSceneAssets`。
  输入验证失败不写源 Prefab；输入验证通过后，源 Prefab 的 Authoring、LODGroup 或 PrototypeGuid 已保存，后续候选或发布失败不会自动回滚它。
- 首次创建通过移动候选及其 `.meta` 完成正式化；刷新只替换目标 `.asset` 内容并保留既有 `.meta` 和 Unity GUID。候选失败不会触碰旧目标，但文件移动、替换、重导入或保存中途失败没有完整自动回滚保证。
- Prototype 刷新后的多 SceneAsset 更新是逐资产候选编译、验证、写回、保存和通知，不是跨资产总事务。第 N 份失败时，前后资产可能处于不同代际；恢复要求修复后幂等重扫全部引用资产。
- GUID 时机交代完整：
  SceneGuid 在新建 SceneAsset 时生成，但复制资产会复制非空值，当前无全局冲突治理；PrototypeGuid 在临时 Prefab Contents 的 Prepare 阶段补齐，ValidateInput 通过后才写回；候选 Unity GUID 在 `CreateAsset` 时随 `.meta` 产生；刷新保留目标 Unity GUID；Paint 的 StableGuid 由 StrokeGuid 与候选序号确定性生成，Replace/Reproject/Transform 和跨 Heap 移动保留它，真正复制新株才生成新身份；正式 Heap 到 Commit 才创建，HeapGuid 可由 SceneGuid 和 Heap 坐标确定性生成。
- PrototypeId 只是单个 SceneAsset 内的槽位索引，实例不直接保存 PrototypeGuid；RuntimeIndex、数组下标和 GPU Slot 都是易变派生地址。跨 SceneAsset 的外部身份必须使用 `(SceneGuid, StableGuid)`，并先保证 SceneGuid 唯一。
- 五种 Painter 模式的边界明确：
  Paint/Erase 在笔划内暂存、抬起自动形成一个 Undo；Replace/Reproject/Transform 抬起只完成选择，显式应用才提交一个 Undo。Commit 前取消不写资产；Transform 取消还要撤销 BRG 临时补丁。
- 范围操作以 `StableGuid + Scene Revision` 建快照并在应用前重验。记录也诚实指出 Revision 会随 Unity Undo 回退，可能发生旧 Stage 表面重新匹配；Undo/Redo 主动清空全部 Stage 与预览补丁仍是待改进项。
- Heap 只为实际触及区域建立 Stage；取消不会留下正式 Heap。Commit 才创建新增或跨 Heap 所需目标 Heap，空 Heap 在写回/编译阶段删除。Heap 内按 `PrototypeId → Morton 码 → StableGuid` 排序。
- Reproject/Transform 跨 Heap 时保留 StableGuid，同时重新编译源、目标 Heap，并按新视觉 Bounds 中心重新采样光照；Replace 也不会把旧位置或旧模式的光照字节冒充成有效结果。StableGuid 用于身份重绑，不代表自动复用旧压缩光照。
- 失败边界覆盖充分：对话框取消、运行时 Cell 创建失败、Prototype 候选失败、文件发布失败、第 N 份引用资产失败、Commit 校验失败、写回中断、Compile 部分成功、Save 结果不确定、通知或 BRG 刷新失败均区分了内存作者数据、磁盘状态、Stage、派生缓存和恢复责任。
- Unity Undo/Redo 恢复同一个序列化 SceneAsset 后，宿主会强制重建全部已加载有效 Cell，而不是只刷新当前 Authority；回调不主动保存，因此画面与内存一致不能证明磁盘已同步。
