## 独立主题复述

本文讲述一条面向无逐株 `MeshRenderer` 的 BRG 植被静态光照链：

1. Bakery Full Render 前生成临时、仅投影的合并代理。
2. Bake 结束、失败或取消后同时清理 Unity 对象和 Bakery Storage 引用。
3. 在代理清理后恢复或烘焙 L2 Probe，并保存、校验 `LightingDataAsset`。
4. 按植被实例位置采样，将光照压缩为 8 B 或 20 B 稀疏记录。
5. 运行时由 BRG Shader 通过 Heap、模式和稀疏索引消费。

适用范围明确限定为 Unity 2022.3 LTS、URP 14、BRG 与 Bakery 1.98 的参考集成。本文明确不负责逐株 Lightmap、完整 32 B 实例 ABI、动态 BlendProbes、目标设备性能结论，也没有宣称当前流程已经达到生产可用状态。

## 内部一致性与证据边界

- 代理生成顺序始终为 Heap → Material → 顶点容量分块；LOD0、Alpha Clip、Cull、`ShadowsOnly`、`LightProbeUsage.Off` 和 `ScaleInLightmap = 0` 的职责互相一致。约 400k 顶点被正确描述为容量护栏，而不是通用安全值。
- Bakery Storage 引用与代理对象被视为同一个清理事务的两个表面。正常、失败、取消和脚本异常都要求进入幂等清理；正文也明确指出当前缺少清理后零残留硬门禁。
- “无代理 Probe”没有被不当宣称为已证明状态。全文反复指出当前只能确认 Cleanup 被调用，不能确认代理、生成目录和 Storage 引用为零。
- L2 恢复顺序内部一致：第一次恢复先写入并保存 `LightingDataAsset`，然后校验；刷新阶段再次恢复并保存，之后才编译、保存 SceneAsset 和发布。失败矩阵正确反映了这一非原子顺序。
- 逐株采样点、`StaticLightColor` 的单方向最终颜色，以及 `StaticBakerySh` 的方向性表示之间没有混用。
- 8 B/20 B 均被限定为稀疏光照 payload；每 Heap 128 B 是量化参数；32 B 实例记录只携带寻址信息。三者没有被错误相加或互相替代。
- HLSL 消费描述与数据表一致：颜色模式直接取最终颜色，SH 模式按顶点法线做方向评估。
- 多运行时 Cell 与多 Unity Scene 被明确区分。临时对象按源 Scene 与 SceneAsset 定位，但正文没有把这种定位能力夸大为 Bakery 多 Scene 输出已正确隔离。
- Prototype 刷新、重新采样和完整重烘焙的触发条件总体一致：采样中心或模式变化不必无条件重烘焙；投影几何、材质语义或场景照明失效时必须重跑完整链。
- Domain Reload、Bake 世代缺失、多 Scene 全局 Probe 状态，以及保存成功后通知失败，均被当作不同问题处理。
- 整 Cell 卸载职责没有混入编辑器 Bake 清理：运行时 Buffer 与量化参数归加载 Cell 所有，代理和 Storage 属于 Bake 临时生命周期。

证据强度总体合适。历史 Bakery 1.98 Bake、当前 Windows Editor ABI 回读、旧版 Quest 数据和未执行的当前设备验证被明确分开；正文没有声称已经重跑 Bakery 作者链或已经完成生产验收。
