2. 独立复述

文章处理的是：没有逐株 `MeshRenderer` 的 BRG 植被，如何既参与 Bakery 静态 Lightmap 的投影，又获得逐株 Probe 间接光，同时不把场景专属结果写进跨场景 Prototype。

完整流程分成两条职责明确的路径：

- Full Render 前，按 Scene、Cell、Heap、Material 和顶点上限，把植被 LOD0 临时合并成只投射阴影、不占 Lightmap 图集的代理 Renderer，使 Bakery 能看见原本只有 BRG 数据的植被几何。
- Full Render 结束后，必须先验证本次输出、清除代理 GameObject、临时 Mesh 和 Bakery Storage 引用，并证明零残留；随后在无代理状态下烘焙或验证 L2 Probe。之所以不能带代理烘 Probe，是因为辅助投影几何会改变运行时并不存在的遮挡环境。
- 每株以可见 Bounds 中心作为唯一世界采样点，从 Unity Probe 插值得到完整 RGB×9 的 `SphericalHarmonicsL2`。Occlusion Probe 虽被 API 返回，但当前不会保存；Probe 覆盖范围外也没有项目自定义回退，因此生产场景必须覆盖全部采样点。
- `StaticLightColor` 用实例向上方向对完整 L2 求值，把结果固化为 RGB，再按 Heap 做 12 bit 量化并存入 8 B 对齐记录。它保留这个位置、这个方向的最终颜色，但失去换法线重新求值、同株空间变化、Occlusion 和量化外精度。
- `StaticBakerySh` 从完整 L2 提取每个颜色通道的常量项和一阶方向项，形成三组 `Ar/Ag/Ab`；部分二阶系数被丢弃，系数 0 与 6 折叠后也不可分别恢复。12 个参数按 Heap 做 12 bit 量化，理论 144 bit，装入五个 `uint`，即每株 20 B。运行时结合顶点世界法线做 Geomerics 方向评估，能保留随法线变化的明暗，但不能恢复完整 L2。
- 场景实例、Heap 和逐株光照归 SceneAsset 所有；Prototype 只持有可跨场景复用的网格、材质、Bounds 和模式声明；运行时 Heap 还持有解量化参数和 BRG Buffer。文章也解释了 8 B/20 B 稀疏记录、32 B 主记录和每 Heap 128 B 参数各自的职责。
- 当前实现已有 happy path、结构性 Lightmap 检查、清理尝试、唯一 Scene 下的无代理 Probe 和 SceneAsset 刷新，但 Finished 事件并不能证明 Full Render 是本次、完整且无新旧混合，也不能证明清理零残留。
- 生产方案因此要求 Bake ID、逐 Scene 输入/输出清单、预期接收 Renderer、本次输出身份、部分写入识别、零残留、Probe 与 Scene/Bake 身份绑定，以及失败时成对恢复 LightingDataAsset、Bakery Storage/Lightmap 和 SceneAsset；不能依赖 Undo 或“列表非空”。
