# 陌生读者冷读证据

本目录保存新增记录或正文实质改写的冷读证据。它属于系统审核层，不是 `data/*.md` 用户知识，也不得作为知识查询结果返回。

## 何时必须冷读

- 新增正式记录；
- 标题、概要、状态、正文结构、技术数字、代码、步骤、方案、因果链、适用范围或结论发生实质变化；
- 架构、排障、迁移、研究综合等依赖背景较多的内容发生修改；
- 正文直接引用资源的路径集合或任一资源内容发生变化。

只有同时不改变正文语义、Markdown 渲染结构、目录锚点、链接目标、代码、元数据和读者行动的记录文本变化，才可能走机械继承。日期、标签、来源目标、标题、概要、状态、技术数字、代码、步骤、结论、章节顺序，以及 `#`、反引号、列表符、链接括号等 Markdown 定界符的变化，都不能默认豁免完整冷读。

学习用途本地留档不得按冷读意见改写外部原文。读者只审核本地概要、元数据、导航、来源与适用说明、原文/资源完整性；原文自身依赖背景时，在本地说明中标注。

## 目录与命名

```text
references/reviews/<record-name>/<YYYY-MM-DD>-<sha256前12位>.md
```

`<record-name>` 与目标 `data/<record-name>.md` 一致。一个证据文件只能对应一个完整候选 SHA-256；目标记录发生实质变化后必须生成新证据，不得覆盖旧证据伪装成同一次审核。

## 必填内容

```markdown
# 冷读审核：<记录标题>

- 目标记录：`data/<record-name>.md`
- 候选 SHA-256：`<完整 64 位摘要>`
- 直接引用资源：`<相对路径> <完整 SHA-256>`（无则写“无”）
- 审核日期：YYYY-MM-DD
- 审核任务/上下文 ID：`<运行环境返回的可追溯标识>`
- 读者隔离：`<新上下文的创建方式，例如 fork_turns=none>`
- 输入白名单：目标记录、正文直接引用的资源、目标读者画像、审核问题
- 目标读者：<具备的普通基础，以及明确不具备的项目知识>
- 最终结论：可发布 | 修改后发布 | 无法判断

## 完整审核提示

<逐字保存实际发送给读者的完整提示；不得补写未发送的约束>

- 结论前目标 SHA-256：`<完整摘要>`
- 阅读前资源摘要：<逐项列出，无则写“无”>
- 结论前资源摘要：<逐项列出，无则写“无”>

- 复算时间：YYYY-MM-DDTHH:MM:SSZ

- 最终直接引用资源：`<相对路径> <完整 SHA-256>`（无则写“无”）
```

## 真实性要求

- 委派前冻结目标记录，计算完整 SHA-256，并记录直接引用资源的相对路径与 SHA-256；审查返回前不得修改这些输入。读者必须在阅读前和给出结论前分别重算，二者不一致时结论只能是“无法判断”。
- 读者必须使用不继承父任务历史的新上下文，只能只读访问输入白名单，禁止修改文件和 Git 状态。
- 必须记录审核任务/上下文 ID、无历史上下文的实际创建方式、完整审核提示和实际输入白名单；缺少任一项时不得声称独立冷读完成。
- “读者完整原始输出”必须逐字保存，不能由作者压缩、改写、润色或只保留通过结论。
- “修改后发布”和“无法判断”均不能发布。修复阻断项、实质修订或直接引用资源变化都必须让新候选重新获得“可发布”；只有满足下方全部机械规则的记录文本变化，才能凭连续继承链到达最终 SHA。
- 只有非阻断建议可以说明理由后保留；发布阻断项不能靠作者声明豁免。
- 保存证据后、提交前，发布执行者必须重算目标记录和正文直接引用资源的完整路径集合及摘要，把时间与结果写入“发布前复算”，并与证据逐项匹配；不一致时必须重新冷读或按下方机械继承流程处理。

## 审核问题与输出

读者在不知道作者意图和实现对话的前提下，至少检查：

- 能否复述文章的适用场景、真实问题、核心结论和端到端机制；
- 术语、依赖、因果、证据、兼容关系、失败方式和适用边界是否足以独立理解；
- 经验记录是否说明场景与症状、根因、方案为何有效、验证与边界；
- 架构或流程记录是否说明输入怎样经过组件形成用户可观察的输出，以及失败恢复、迁移和代价；
- 结尾是否给出可执行步骤、采用检查、适用/不适用条件、风险或明确结论；
- 相关记录和外部链接是否仅作扩展，而非替代当前正文的核心说明。

读者完整输出必须包含：

1. **读者复述**：用自己的话复述主旨和机制，以暴露理解偏差。
2. **阻断问题**：指出缺失背景、未解释术语、跳跃因果、隐含上下文、虎头蛇尾或无法执行之处，尽量定位到具体章节。
3. **非阻断建议**：说明可改进但不影响发布的结构或表达问题。
4. **明确结论**：只能是“可发布”“修改后发布”或“无法判断”。

收到“修改后发布”后，只根据明确阻断项和新证据做一轮定向修订，再对新候选完整冷读。复审仍出现同一阻断且没有新证据时立即停止，交付当前候选、阻断证据和恢复所需条件；不得靠反复改写撞结论，作者也不能用异议豁免发布阻断项。

## 机械修正继承证据

完整冷读后若记录文件发生机械修正，不能继续声称最终 SHA 与旧证据一致。只有变化同时不改变正文语义、Markdown 渲染结构、目录锚点、链接目标、代码、元数据和读者行动，并且直接引用资源的路径集合与内容摘要完全不变时，才允许保存：

```text
references/reviews/<record-name>/<YYYY-MM-DD>-<新sha前12位>-mechanical.md
```

继承证据必须包含：上一份“可发布”证据路径、旧/新完整记录 SHA-256、旧/新两套直接引用资源路径与摘要清单、非作者复核者在复核起止时独立重算的记录与资源摘要、精确文本 diff、渲染与链接核对结果、复核任务/上下文 ID、复核提示和逐字输出，以及结论“可继承”或“需重新冷读”。两套资源清单只要有一项不同，就不得机械继承，必须对新候选重新完整冷读。

保存机械证据后还必须写入一次发布前复算：复算执行者、时间、最终记录 SHA-256、最终直接引用资源路径与摘要清单，以及与机械证据逐项匹配的结论。缺少任一项、复核者是作者本人、最终复算不匹配或复核结论不是“可继承”时，都必须重新完整冷读。多次机械修正必须形成逐步相连的证据链，禁止跨过中间版本笼统继承。
