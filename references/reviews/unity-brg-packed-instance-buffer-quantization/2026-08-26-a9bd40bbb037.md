## 系统复述

该 ABI 仅接受有限位置、正数统一缩放、无剪切、无镜像、正手性且可恢复有限单位四元数的 TRS。统一缩放误差阈值为 `0.001`，轴正交误差阈值为 `0.001`，手性下界为 `0.999`；不可表达输入必须在 CPU 打包前失败。

每实例固定 `32 B = 8 uint`：

| uint | 字节 | 内容 |
|---:|---:|---|
| 0–2 | 0–11 | position.x/y/z 的 binary32 原始位 |
| 3 | 12–15 | smallest-three：`a[0..9]`、`b[10..19]`、`c[20..29]`、`omitted[30..31]` |
| 4 | 16–19 | scale Half 在低 16 位，random UNorm16 在高 16 位 |
| 5 | 20–23 | maxWind Half 在低 16 位，minY Half 在高 16 位 |
| 6 | 24–27 | invHeight Half 在低 16 位，HeapIndex 在高 16 位 |
| 7 | 28–31 | lightingRecordIndex 在低 31 位，lightingMode 在 bit 31 |

完整运行链是：高精度局部 TRS 与 Cell Transform、Floating Origin 合成世界矩阵，完成表达域验证后，在临时完整候选中编码；按 Heap 展开顺序上传共享 Buffer；`visibleInstances` 写入 GlobalSlot；HLSL 两次读取 `uint4`，恢复 TRS、风摆、Bounds、Heap 和光照索引；Forward、Depth、DepthNormals、Shadow 共享取数与世界形变链。

CPU 剔除从同一编码重新解码旋转和缩放，中心、半径及 LOD 使用量化后真值；影响最大位移的 Half 参数取 `max(source, decoded)`，Heap Bounds 只允许保守扩大。

批量预览和 Rebase 都先构造、验证和上传完整候选，再提交公开状态。HeapMask 只影响剔除，不压缩或释放失活 Heap 数据。整 Cell 卸载才等待 CPU Job、移除 Batch，并释放 Buffer、NativeArray 和 Prototype 引用。

## 数值与寻址规范审核

- Smallest-three 的位偏移、`x→y→z→w` 保留顺序、严格 `>` tie-break、负最大分量时整体取反均已冻结。
- `R` 固定为 binary32 位型 `0x3F3504F3`。除、乘、加按书写顺序分别以 binary32 求值；midpoint 固定为 nearest、ties-to-even，排除了高精度延迟舍入、FMA 合并和 ties-away 等字节分歧。
- 合法编码输入从“已提取、已归一化的有限四元数”开始。Unity 矩阵经轴归一化和 `LookRotation` 生成四元数明确属于生产者协议；非 Unity 生产者若从矩阵起步，必须额外复刻该协议。这不是 ABI 编码器内部的未冻结选择。
- identity 金样的三个零分量都量化为 `512`，连同 omitted=`w=3` 得到 `E0080200`，正确。
- UNorm16 接受任意有限 binary32，先钳制 `[0,1]`，再以 binary32 乘 `65535` 并 ties-to-even；解码固定为 `q/65535.0f`。`0.5` 得到 `0x8000`，与金样一致。
- NaN/Infinity 明确不属于随机相位合法域。记录诚实说明当前打包帮助函数没有独立门禁，现阶段由稳定身份生成器/调用方保证有限 `[0,1]`。
- Half 固定到 Unity.Mathematics 1.3.2 的位算法，而非泛称 IEEE Half。公式明确冻结掩码、binary32 乘法、上界、加法、移位和符号拼接；`+0→0000`、`-0→8000`、最小次正规数 `→0001`、`123.4→57B6`、`65504→7BFF` 均与算法一致。
- Half 合法域为有限且 `abs(value) <= 65504`。正语义字段先拒绝 `<=0`，再拒绝量化为零；一般 Half 字段保留 signed zero。移动 GPU 次正规数是否 FTZ 被明确列为未验证边界。
- 8 uint 金样逐字一致；其中 Bakery SH 模式通过 `80000009` 冻结为 bit31=`1`，因此另一种二态模式为 `0`。规范单位是八个 32 位字，连续字节导出明确限定 little-endian；big-endian 不在适用范围。
- Packed Metadata 为 `0x80000000 | PackedInstanceBase`，`visibleInstances` 值就是 GlobalSlot。`ComputeDOTSInstanceDataAddress(metadata,32)` 只追加一次 `GlobalSlot×32`，Shader 禁止再次追加。示例 `96 + 5×32 = 256`、两次读取 `[256,271]` 和 `[272,287]` 正确；重复追加会错误到 `416`。
- 风场、Heap 量化表和两张光照表均使用无最高位的共享 Metadata，以 stride `0` 获取基址，再显式追加 `HeapIndex×128`、记录索引 `×8` 或 `×20`。
- 位宽检查与逻辑域检查均存在：`HeapIndex < logicalHeapCount`，光照索引小于对应模式表的 logicalCount。空表只分配哨兵，不生成 DrawCommand。
- checked Int32 计算、16 B 对齐及 `TotalBytes < 2^31` 共同保护 Metadata 基址；结合逻辑索引上界，可保证 `base + index×stride + loadWidth` 不越过已分配区间。
- 三组公式样本复算一致：
  - `288/40/144/144`：新 `18,464 B`，旧 `46,112 B`，减少 `27,648 B = 96×288`，降幅 `59.958%`。
  - `8192/50/8192/0`：新 `334,208 B`，旧 `1,120,640 B`，减少 `786,432 B`，降幅 `70.177%`。
  - `8192/1024/8192/0`：新 `458,880 B`，旧 `1,245,312 B`，减少 `786,432 B`，降幅 `63.151%`。
- 合法 codec 输入域内，没有发现两个看似合规编码器仍可生成不同字节的未冻结选择。
