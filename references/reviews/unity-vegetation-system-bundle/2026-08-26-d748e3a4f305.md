## 组合复述

Prefab 是原型烘焙的作者输入，不是逐株运行时权威。烘焙器在隔离的 Prefab Contents 中读取 Authoring、LOD、Renderer 和显式碰撞子树，生成带 `PrototypeGuid` 的 Prototype。Prototype 保存可跨场景复用的 Mesh、Material、LOD、视觉 Bounds、风摆上限、碰撞描述和光照模式声明，不保存场景实例位置或逐株光照。SceneAsset 以 `PrototypeTable` 提供本资产内的 `PrototypeId` 映射，并保存 Heap、实例局部 TRS、StableGuid 和逐株场景数据。

一个运行时 Cell 是“管理器 + 一份 SceneAsset + 一套独立渲染和物理资源”；Heap 是其中的空间块。统一架构文中历史性的通用 `Cell` 在映射当前实现时通常指 Heap，只有明确写“运行时 Cell”时才指更大的加载和所有权边界。

Painter Authority 是当前唯一允许被 Painter 写入的运行时 Cell。多个运行时 Cell 可以同时拥有各自 BRG 会话，但同一时刻只有一个作者 Authority。`HeapStage` 是一次操作实际触及 Heap 的内存候选副本，不是正式数据；Unity 的 Prefab Stage 则是视图和场景隔离上下文，两者不是同一概念。Preview 同样不是权威数据：Paint/Erase 预览影响范围，Replace/Reproject 预览目标集合，只有 Transform 会补丁 BRG 矩阵及 CPU Bounds，形成真实结果预览。

Commit 校验 Stage、登记完整 SceneAsset Undo、把作者数据写回内存、创建或删除 Heap并标脏，但不等于磁盘已保存。Compile 清理空 Heap，按坐标和 `PrototypeId → Morton → StableGuid` 排序，生成 RuntimeIndex、Bounds、光照表和 Hash。Save 才保存整个 SceneAsset；PublishNotification 再通知宿主刷新正式 BRG。当前普通增量 Compile 仍可能逐 Heap 写回，作者 Undo、派生缓存、磁盘保存和 BRG 刷新没有被证明为统一的两阶段原子事务。

StableGuid 是实例在单个 SceneAsset 内的持久身份。跨资产引用需使用 `(SceneGuid, StableGuid)`，但当前资产复制可能复制 SceneGuid，且没有全局冲突治理。RuntimeIndex 只在 Heap 内连续；加载时按 SceneAsset 当前 Heap 顺序累计前序实例数得到 HeapBase：

```text
GPU Slot = HeapBase + RuntimeIndex
```

StableGuid 在跨 Heap Transform/Reproject 中保持不变；RuntimeIndex、HeapBase 和 GPU Slot 都是当前编译或加载快照的派生地址，不能保存为持久外部引用。

当前固定逐株记录为 32 B，即八个 `uint`：

```text
0–11 B   世界位置 float3
12–15 B  smallest-three 旋转：a[0..9]、b[10..19]、c[20..29]、omitted[30..31]
16–19 B  低 16 位统一正缩放 Half；高 16 位随机相位 UNorm16
20–23 B  低 16 位最大风摆 Half；高 16 位 Bounds 最低点 Half
24–27 B  低 16 位 Bounds 高度倒数 Half；高 16 位 HeapIndex
28–31 B  最高位 LightingMode；低 31 位对应稀疏光照记录索引
```

它只接受有限、无剪切、非镜像、正数统一缩放。CPU 剔除使用同一 ABI 解码后的 TRS，并对影响风摆 Bounds 的 Half 取源值与恢复值的较大者形成保守包络。历史 128 B 是固定逐株区的旧矩阵布局；当前 32 B 不包含额外的 8 B/20 B 稀疏光照 payload，也不包含每 Heap 128 B 量化表。

Raw Buffer 是按数据表分段的逻辑布局，但逐株 Packed Instance 段内部是 32 B AoS Record，不是字段级 SoA：

```text
64 B 合法零地址哨兵
+ 16 B Cell Wind
+ 16 B Cell Wind Spatial
+ 32 B × max(1,N)
+ 128 B × max(1,H)
+ 8 B × max(1,C)
+ 对齐
+ 20 B × max(1,S)
+ 总对齐
```

DOTS 逐株寻址为：

```text
metadata = 0x80000000 | PackedInstanceBase
instanceIndex = visibleInstances 元素 = GlobalSlot
address = (metadata & 0x7FFFFFFF) + instanceIndex × 32
```

HLSL 的 `ComputeDOTSInstanceDataAddress(metadata, 32)` 清除最高位，并在 PerInstanceDataBit 存在时只追加一次实例偏移；Shader 不能再手工追加 Slot。风场、Heap 量化表和两张光照表的 Metadata 不设置最高位，HLSL 从共享基址自行追加 `HeapIndex×128`、`LightingRecordIndex×8` 或 `LightingRecordIndex×20`。

运行时 Cell 加载时创建独立 BRG、单 Raw Buffer、剔除快照、QueryWorld 和 ColliderStreamer；按 Heap 顺序一次上传全部实例与共享表。每个 Cell 的 HeapMask 是按当前 Heap 顺序索引的一字节门禁。它只决定 Heap 是否继续进入剔除，不会上传、缩容、释放或真正卸载 Heap。

每个视图当前执行：

```text
Heap 粗筛
→ 对本 Cell 全部实例执行 Count
→ LOD / RenderBucket 分类
→ Prefix
→ 对本 Cell 全部实例执行 Scatter
→ visibleInstances / DrawCommand
```

失活 Heap 只在 Job 内提前退出，所以复杂度仍近似 `O(本 Cell 总实例数 × 视图数)`。多个运行时 Cell 共享兴趣源，但不共享 SceneAsset、BRG、Buffer、HeapMask、QueryWorld、ColliderStreamer 或代理池；激活预算和 `Physics.SyncTransforms` 仍按 Cell 计算，没有全局物理调度器。

Rebase 只改变累计 Floating Origin，不重新计算 HeapCoordinate、不重新分桶、不改 SceneAsset、StableGuid、RuntimeIndex、HeapBase 或 GPU Slot：

```text
renderMatrix =
Translate(-absoluteOriginOffset)
× CellTransform.LocalToWorld
× authoredCellLocalTRS
```

渲染入口接收新的累计绝对偏移，从高精度作者 TRS 重建候选 32 B Buffer 和剔除快照；物理侧接收本次 `delta`，把 QueryWorld、Collider 缓存描述及活动代理平移 `-delta`。当前只有分离入口，没有把所有 Cell、渲染、查询和 PhysX 原子广播的内建全局协调器；接入方需用同一世代分发 absolute origin 与 delta。

QueryWorld 常驻解析 Sphere、Capsule、Box，不依赖 PhysX 代理；ConvexMesh 只走 ColliderStreamer。大集合使用每运行时 Cell 独立的 Heap/Shape 两级懒建 BVH，阈值为 64、叶容量为 8，小集合继续线性。当前已明确存在一个生产正确性缺口：外层 Query Heap Bounds 复用了视觉 Bounds，未保证包含全部外伸 Query Shape，可能产生确定性假阴性。

ColliderStreamer 按运行时 Cell 独立维护 LoadRadius、UnloadRadius、Cooldown、实例状态和代理池。激活预算按实例计，不按 Collider Shape 数计；一个获批实例若有 N 个 Shape，会在同次激活取得 N 个 Proxy。多兴趣源形成 DesiredReferenceCount 和 RetainReferenceCount。整个 Cell 卸载时，物理侧按实际注册记录反注册 Heap、归还代理并 Dispose QueryWorld。

Bakery 链先在 Full Render 前为启用投影的 Cell 创建按 Heap、Material 和顶点护栏分块的临时代理；代理为 `ShadowsOnly`、`LightProbeUsage.Off`、`ScaleInLightmap=0`。Bake 结束、失败或取消都应清理代理对象、临时 Mesh 和 Bakery Storage 引用。当前实现会尝试清理，但尚无“代理根、目录、Storage 引用均为零残留”的硬门禁，也没有完整 Bake 世代恢复协议。

需要静态 Probe 时，应在代理清理后进行无代理 L2 Probe，恢复并验证 LightingDataAsset，再由 SceneCompiler 逐株采样。`StaticLightColor` 每株 8 B，是在编译期按局部向上方向求好的最终 RGB；`StaticBakerySh` 每株 20 B，运行时按顶点法线进行方向性评估；两者共享每 Heap 128 B 量化参数。Prototype 刷新只重编译引用或保留旧记录，不等于重跑 Bakery；当 Mesh、LOD、Material、Alpha Clip、Cull 或其它投影语义变化时，目标 Scene 必须重跑完整 Lightmap 链，必要时再跑无代理 Probe。

Quest 数字来自 2026-08-19 历史 APK 的四组 BRG→普通 GO→BRG A/B/A：

- 稀疏真实草约 `90.625 / 90.667 / 90.562 FPS`，设备三段未保存实际可见数。
- 高密度真实草为 `19.938 / 19.938 / 20.000 FPS`，GPU 约 99%，支持其主要受可见几何、双面 Alpha Clip 和 Overdraw 限制。
- 大 Box 为 `83.250 / 71.812 / 84.875 FPS`。
- 15% Box 为 `90.500 / 81.500 / 90.600 FPS`，且只有该组保存了三段同 PID。

这些是完整系统路径对比：历史 BRG 使用逐株 StaticLightColor，普通 GO 使用 GameObject、Renderer、LODGroup 与 BlendProbes，不是仅替换 Draw API。不同几何 APK 之间同时改变拓扑、轮廓、Alpha Clip 覆盖和 Overdraw，两个 Box APK 还有 31.111% 体积漂移，因此跨包只能作相关性证据。
