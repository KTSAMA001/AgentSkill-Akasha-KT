组合复述

1. 作者输入与权威分层

Prefab 是 Prototype 的作者输入。烘焙器在隔离的 Prefab Contents 中解析 Authoring、唯一 LODGroup、Renderer、视觉 Bounds、风摆范围、显式碰撞子树和光照模式。Prefab 不会成为逐株运行对象。

PrototypeAsset 是可跨场景复用的静态描述，保存 Mesh、Material、LOD、视觉 Bounds、碰撞描述和光照模式，以 PrototypeGuid 表示稳定种类。它不保存某个场景的逐株位置或逐株静态光照。

SceneAsset 是一个运行时 Cell 的植被作者权威，保存 PrototypeTable 和多个内嵌 Heap。实例只保存本资产内的 PrototypeId、StableGuid 和 Heap 局部 TRS。跨资产引用应使用 `(SceneGuid, StableGuid)`；当前复制 SceneAsset 可能复制 SceneGuid，仍需要额外治理。

一个运行时 Cell 是“管理器 + SceneAsset + 独立 BRG/Buffer/物理资源”的加载和释放边界；Heap 是其内部空间块。通用架构文中的普通 Cell 映射到当前实现的 Heap，不能与运行时 Cell 混称。

2. Painter 作者事务

Painter 同一时刻只取得一个运行时 Cell 的作者 Authority。多运行时 Cell 可以同时拥有独立渲染会话，但不能同时成为 Painter 写入目标。

Paint、Erase、Replace、Reproject、Transform 都先进入内存暂存。HeapStage 只为实际触及的 Heap 建立副本，不是权威数据。

反馈分三类：

- Paint/Erase 反馈表示本笔影响范围。
- Replace/Reproject 反馈只表示候选和待处理目标。
- Transform 才会补丁 BRG 矩阵和 CPU Bounds，形成真实结果预览。

Commit 前取消只丢弃 Stage、目标快照或预览补丁，不修改 SceneAsset，也不产生 Undo。

正式 Commit 校验 Stage、登记完整 SceneAsset Undo、写回作者实例、创建或删除 Heap并标脏。首次 Paint 只在 Stage 中触及坐标；Heap 首次成为 SceneAsset 中的正式权威记录，是 Commit 调用正式创建入口时，不是在鼠标命中、Stage 或 Preview 阶段。

跨 Heap 移动保持 StableGuid，只更新 Heap 归属和局部 TRS。数组下标、RuntimeIndex 和 GPU Slot 都不能替代 StableGuid。

Compile 清理空 Heap并排序；Heap 内实例按 PrototypeId、Morton、StableGuid 排序，重新分配 Heap 内连续 RuntimeIndex，再生成 Bounds、光照表和内容 Hash。Save 把整份 SceneAsset 写盘；PublishNotification 再通知宿主刷新 BRG。Commit、Compile、Save、通知不是一个跨文件原子事务。

3. 编译索引与运行时地址

身份和地址链为：

StableGuid
  -> 持久作者身份
  -> Compile 后的 Heap 内 RuntimeIndex
  -> 运行时 Cell 加载时派生 HeapBase
  -> GPU Slot = HeapBase + RuntimeIndex
  -> 当前单 Batch 下 BatchLocalIndex = GPU Slot

RuntimeIndex 是编译派生地址；HeapBase、GPU Slot 和 BatchLocalIndex 是加载后临时地址。它们都可能在重编译或 Heap 顺序变化后改变。

4. 渲染加载、剔除与多 Cell

运行时 Cell 加载时独立创建 BRG、Raw Buffer、剔除快照、QueryWorld 和 ColliderStreamer。当前路径按 SceneAsset 的 Heap 顺序扫描，一次上传该 Cell 的全部 Heap 和全部实例。

每个运行时 Cell 独立持有 HeapMask。兴趣源距离和迟滞只更新掩码位。HeapMask 只门控本次剔除是否继续处理某个 Heap；它不表示 Heap 资源已单独加载或卸载，也不触发 Heap 级 Buffer 上传、缩容或释放。

每个 Camera/Light 视图执行：

Heap 粗筛
  -> 对本 Cell 全部实例调度 Count
  -> 失活 Heap 的实例在 Job 内提前退出
  -> LOD 与 RenderBucket
  -> Prefix
  -> 对本 Cell 全部实例调度 Scatter
  -> visibleInstances 与 DrawCommand

所以 HeapMask 能减少细处理和绘制，但 Count/Scatter 调度长度仍是运行时 Cell 总实例数，复杂度仍近似“Cell 总实例数 × 视图数”。当前不是紧凑实例工作集。

多个运行时 Cell共享兴趣源，但不共享 SceneAsset、BRG、Raw Buffer、HeapMask、QueryWorld、ColliderStreamer、ProxyPool、半径或预算。

5. QueryWorld 与 Collider 流送

运行时 Cell 加载时，从 Prototype 碰撞描述和实例变换生成两套物理数据：

- QueryWorld 保存解析 Sphere、Capsule、Box，用于 Raycast、Overlap、Sweep；ConvexMesh 不进入此路径。
- ColliderStreamer 保存可生成真实 PhysX Collider 的实例描述；一个实例可以对应多个 Shape 和多个 Proxy。

QueryWorld 是每运行时 Cell 独立的两级懒建索引：

- Heap 数少于 64：线性枚举 Heap。
- Heap 数至少 64：首次查询时懒建顶层 Heap BVH。
- 候选 Heap 的 Shape 少于 64：线性枚举 Shape。
- Shape 至少 64：该 Heap 首次成为候选时懒建 Shape BVH。
- BVH 只缩小候选集合，解析窄相位仍继续执行；大范围、长射线、重叠或同中心 Bounds 的最坏情况仍可能接近线性。

ColliderStreamer 每固定步聚合兴趣源的位置、速度预测和优先级，分别计算 DesiredReferenceCount 与 RetainReferenceCount，推进：

Inactive
  -> Desired
  -> Active
  -> Cooldown
  -> Inactive

激活预算按实例计，不按 Proxy 计；一个实例获批后会一次取得全部 Shape 的 Proxy。AllResident 绕过该实例预算。若本步代理发生增删或变换，每个 Streamer 最多统一执行一次 Physics.SyncTransforms。预算和同步次数均按运行时 Cell 隔离，目前不是全世界统一预算。

已知 Query Heap Bounds 假阴性非常醒目：物理记录在概要后明确警告“有效状态不代表可直接作为生产正确性门禁”，生成章节说明外层 Bounds 必须包含全部 Query Shape，后部又以“已确认的正确性问题”单列根因、确定性失败方式和修复方向，采用清单再次标记当前不满足；统一架构的覆盖表也提前提示该风险。它没有被埋在一般建议中。

6. Bakery 静态光照

Full Render 前，为启用投影的运行时 Cell按 Heap、Material 和顶点容量分块生成 LOD0 合并代理。代理使用 ShadowsOnly、LightProbeUsage.Off、ScaleInLightmap=0，并作为静态 GI 投影物。未启用投影的 Cell 不生成代理，但仍可能是 Probe 和 SceneAsset 编译目标。

Full Render 结束、失败或取消后，系统尝试同时清理代理对象、临时 Mesh 和 Bakery Storage 引用。当前缺少可执行的 post-clean 零残留门禁，因此 Cleanup 返回不能直接等同于“已证明无代理”；生产采用仍应验证代理根、生成目录和 Storage 本世代引用均为空。

需要静态 Probe 时，应在代理清理后、唯一目标 Scene 条件下执行无代理 Bakery L2 Probe。恢复链先把 SH 写入并保存 LightingDataAsset，再校验 L2、数量、位置和系数；刷新入口还会再次恢复和保存，随后 SceneCompiler 才采样并写 SceneAsset。LightingDataAsset、SceneAsset 与 BRG 发布不是一个事务。

SceneCompiler 在每株 VisualRootSpaceBounds.center 采样：

- StaticLightColor：8 B 稀疏 payload，运行时直接读取最终 RGB。
- StaticBakerySh：20 B 稀疏 payload，运行时按顶点法线执行方向性评估。
- 每 Heap 另有 128 B 量化参数。
- 每株固定 GPU 数据约 128 B，不能把 8 B/20 B 写成完整实例成本。

7. 卸载

HeapMask 置零不会释放 Heap 资源。当前真正释放发生在整个运行时 Cell 卸载：

停止新读取
  -> 等待已有剔除 Job
  -> 从 BRG 可回调状态移除会话
  -> 释放剔除 NativeArray、Prototype 引用、Batch、GraphicsBuffer 和 BRG
  -> 物理侧按实际注册列表反注册 Heap
  -> 归还全部 Proxy
  -> Dispose QueryWorld
  -> 清空 HeapMask 和运行引用
  -> 外层 Scene/AssetBundle/资源句柄决定 SceneAsset、Mesh、Material 是否最终离开内存

当前可确认 CPU Job 屏障；没有显式 GPU Fence 或异步 Retiring 世代证据，不能把同步卸载描述成完整 GPU 热退役协议。

Compile

  -> 重新采样/生成光照稀疏表
  -> 重算内容 Hash
  -> Save 整份 SceneAsset
  -> PublishNotification
  -> 编辑器宿主按正式资产刷新会话

[运行时加载与寻址]
加载一个运行时 Cell
  -> 创建独立 BRG
  -> 创建独立 Raw Buffer

       GPU Slot = HeapBase + RuntimeIndex
       当前单 Batch：
       BatchLocalIndex = GPU Slot

  -> 发布为可剔除运行会话

[渲染激活]
全局兴趣源
  -> 广播位置/预测/优先级
  -> 每个运行时 Cell 独立计算距离与迟滞
  -> 更新本 Cell HeapMask

HeapMask = 0
  -> 只表示该 Heap 本次不继续剔除
  -> 不卸载 Heap
  -> 不缩小 Raw Buffer
  -> 不释放光照 payload
  -> 不释放 QueryWorld 或 ProxyPool

  -> Prefix
  -> Scatter Job：仍按本 Cell 全部实例调度
       失活 Heap 仅在 Job 内提前退出
  -> visibleInstances
  -> DrawCommand

运行时 Cell 加载

  -> ConvexMesh 不进入 QueryWorld
  -> 每 Heap 缓存 Shape AABB + Purpose Mask

第一次查询
  -> Heap 数 < 64：线性 Heap
  -> Heap 数 >= 64：懒建顶层 Heap BVH
  -> 候选 Heap Shape 数 < 64：线性 Shape
  -> Shape 数 >= 64：该 Heap 首次候选时懒建 Shape BVH
  -> BVH 生成候选
  -> 解析窄相位
  -> StableGuid 结果

[明确正确性门禁]
当前外层 Query Heap Bounds
  -> 来源是视觉 Bounds
  -> 未保证包含全部外伸 Query Shape
  -> 可能在 Heap 粗筛阶段提前拒绝
  -> 后续 Shape 窄相位永不执行
  -> 确定性假阴性
  -> 采用前必须改为独立 Query Bounds
     或合并视觉 Bounds + 全部 Query Shape Bounds
     并补外伸 Shape 回归

[PhysX 代理流送]
每个运行时 Cell 的 FixedUpdate
  -> 获取兴趣源快照
  -> Heap 粗筛
  -> 逐实例计算 Desired/Retain 引用
  -> 确定性候选排序
  -> 在“实例数预算”内激活
       一个实例获批
       -> 为其全部 N 个 Shape 取得 N 个 Proxy
  -> Active 离开 UnloadRadius
       -> Cooldown
  -> Cooldown 到期
       -> 归还全部 Proxy
  -> 本步有代理变更
       -> 本 Streamer 调用一次 Physics.SyncTransforms

[静态光照投影]
Bakery Full Render 前
  -> 遍历受管运行时 Cell
  -> 启用投影：
       Heap -> Material -> 顶点容量分块
       -> 合并 LOD0
       -> ShadowsOnly
       -> LightProbeUsage.Off
       -> ScaleInLightmap = 0
       -> 临时静态 GI 代理
  -> 未启用投影：
       不生成代理
       仍可保留为 Probe/SceneAsset 编译目标

Bakery Full Render
  -> Finished / Cancel / Exception
  -> 幂等 Cleanup 尝试
       - 移除 Bakery Storage 引用
       - 销毁代理 Renderer/根
       - 删除临时合并 Mesh
  -> 生产硬门禁应额外验证：
       - 代理根不存在
       - 生成目录不存在
       - Storage 无本世代引用
  -> 当前实现尚未完整实现此残留硬门禁

[无代理 Probe 与光照发布]
需要 authored Probe 且目标 Scene 唯一
  -> 在 Cleanup 后启动 Bakery L2 Probe
  -> 恢复 SH 到 LightmapSettings
  -> 保存 LightingDataAsset
  -> 校验 L2/数量/位置/系数
  -> RefreshProbeLighting 再恢复并保存
  -> SceneCompiler 按 VisualRootSpaceBounds.center 采样
       StaticLightColor -> 每株 8 B
       StaticBakerySh  -> 每株 20 B
       每 Heap另有 128 B 量化参数
  -> Save SceneAsset
  -> PublishNotification
  -> 重建已加载 BRG

注意：
LightingDataAsset 保存
  != SceneAsset 保存
  != PublishNotification
  != BRG 刷新
它们不是一个事务。

[多运行时 Cell]
兴趣源注册表
  +-> Cell A：独立 SceneAsset/BRG/Buffer/HeapMask/
