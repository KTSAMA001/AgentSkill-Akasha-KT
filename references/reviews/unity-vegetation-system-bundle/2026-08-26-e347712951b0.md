## 系统概念与权威边界复原

- `Prefab` 是作者输入之一，不是运行时权威；它被整理为身份稳定、校验通过的 `Prototype`。
- `Prototype` 保存跨场景复用的 Mesh、Material、LOD、视觉 Bounds、碰撞描述、风摆上限和光照模式声明，不保存场景逐株位置或逐株 Bakery 结果。
- `SceneAsset` 是 ScriptableObject 作者资产，不是 Unity Scene。它是 Prototype 表、Heap、实例、StableGuid、作者修订和逐株静态光照的唯一正式权威。
- 运行时 `Cell` 是“一份 SceneAsset + 一套独立渲染、查询、物理资源”的加载和故障所有权域。
- `Heap` 是 Cell 内部空间块。它组织实例局部坐标、Bounds 和可再生编译信息，但不天然等于 Scene、BRG Batch、Buffer Page 或 Collider 池。
- `Instance` 的持久身份是 SceneAsset 作用域内的 `StableGuid`；跨资产引用需使用 `SceneAssetID + StableGuid`。
- `RuntimeIndex` 是编译快照中 Heap 内的派生下标，重排后可以变化。
- `HeapBase` 是按当前 SceneAsset Heap 顺序扫描、由前序 Heap 实例数形成的派生起点。
- `GlobalSlot/GPU Slot = HeapBase + RuntimeIndex`，是当前加载快照中的地址，不可持久引用。
- `BatchLocalIndex`、`LogicalIndex`、`GlobalSlot` 和 `visibleInstances` 写入位置是不同概念；当前单 Buffer/单 Batch 参考布局中部分数值可能相等，但分页、多 Batch 或多绘制部件会打破这种偶然相等。
- `BRG Session` 持有 BRG、GPU 存储、运行快照和绘制提交权。共享后端是共享协议，不是多个 Cell 共享一个会话。
- `Buffer` 在当前参考实现中是一张按用途分段的 GraphicsBuffer，其中逐株段是 32 B AoS；其它段是 Cell 风场、每 Heap 量化表和两张稀疏光照表。
- `QueryWorld` 是每 Cell 常驻的解析 Sphere/Capsule/Box 查询世界，不依赖 PhysX Proxy 或渲染 HeapMask。
- `ColliderStreamer` 是每 Cell 独占的 PhysX 工作集控制器，只让兴趣源附近实例取得真实 Collider Proxy；ConvexMesh 只走此路径。
- Bakery 临时代理、合并 Mesh 和 Storage 引用只是一次 Bake 的工作集；LightingDataAsset 和 SceneAsset 逐株记录才是后续消费数据，临时代理绝不能成为第二权威。

  → SweepCapsule：候选逐个保守推进，最多 64 次
  → 最终按距离/命中比例/稳定身份等规则收尾
Heap 墀删/替换
  → 顶层索引失效
  → 被替换 Heap 的 Shape 缓存和懒树重建
  → 其它 Heap 的 Shape 树保留
Rebase
  → 平移 Heap、Shape、缓存 AABB 和已建节点
  → 不改拓扑

正确性门禁
  → QueryBounds 包含完整查询体/路径
  → Shape AABB 包含真实 Shape
  → QueryHeapBounds 包含该 Heap 全部 Query Shape
  → 当前最后一条尚未满足，不能生产采用。

[ColliderStreamer 多 Cell 工作集]
全局兴趣源注册表
  → 每个 Cell Streamer 在 FixedUpdate 开始捕获自己的只读快照
  → 输入可共享，QueryWorld、Streamer、ProxyPool、半径和预算按 Cell 隔离
  → 当前快照尚无跨 Cell 原子 Tick 世代

每个固定步
  → 完全 Inactive Heap 用预测线段与 StreamerHeapBounds 粗筛
  → 有 Desired/Active/Cooldown 的 Heap 继续处理
  → 每实例从零聚合 DesiredReferenceCount 和 RetainReferenceCount
  → 未激活且 Desired>0 的实例成为候选
  → 按高速引用、Priority、距离、StableGuid 排序
  → 在每 Cell 的实例激活预算内推进：
      Inactive → Desired → Active
  → 一个实例有 N 个 Shape：
      同次 Activate 取得 N 个 Proxy
      任一失败则全部归还，实例回到 Desired
  → Active 离开 UnloadRadius：
      Active → Cooldown
  → Cooldown 重新进入 Load/Unload 保留区：
      Cooldown → Active
  → Cooldown 到期：
      归还全部 Proxy → Inactive
  → cooldown=0：同一步归还
  → 本步代理有增删或移动：本 Streamer 统一一次 Physics.SyncTransforms
AllResident
  → 跳过流式实例激活预算
  → 仍复用状态机
maxActivationsPerFixedUpdate=0
  → 只暂停新实例激活
  → 不卸载已激活代理

Bounds 链
  ColliderInstanceBounds 包含该实例全部 Collider Shape
  StreamerHeapBounds 包含该 Heap 全部 ColliderInstanceBounds
  这条链当前与 QueryHeapBounds 分开，Streamer 链是保守的。

[统一 Rebase]
newAbsoluteOffset - oldAbsoluteOffset = delta
runtimeNew = runtimeOld - delta
  → 先拒绝非有限 delta
  → 门控新查询和固定步
  → QueryWorld 全部运行时 Bounds/节点平移 -delta
  → Streamer Heap、实例、Shape、Active/Cooldown 借出 Proxy 平移 -delta
  → 兴趣源进入同一坐标基准
  → 丢弃旧候选与旧快照
  → 渲染候选 CPU/GPU 世代一起重建/切换
  → 各子系统确认同一坐标世代后恢复
若外层已平移 Cell 根或兴趣源 GameObject
  → 禁止把同一位移再次作为 delta 施加。

[完整运行时 Cell 卸载]
先停止本 Cell 新查询、固定步评估和 BRG 新快照租约
  → 物理分支：
      按实际成功注册列表逆序调用 Streamer 强清理
      每 Heap 归还全部 Proxy、清状态、反注册
      每个成功项才从所有权记录移除
      任一失败：
          保留原 Streamer、失败 HeapGuid 和诊断
          进入 CleanupFailed
          禁止宣称 Unloaded
      全部 Streamer 所有权解除后：
          Dispose QueryWorld
          清 Shape、缓存和 BVH
          清物理管理器/Transform/HeapGuid 记录
          发布物理 Unloaded
  → 渲染分支：
      Running → Closing，禁止新回调取旧快照
      → Draining，等待全部 CPU Job 租约
      → Retiring，等待 GPU Fence或独立资源世代排空
      → 注销 Batch
      → 释放 Native 容器、Buffer、BRG
      → Disposed
  → 两个分支都完成后，外层 Scene/AssetBundle/资源句柄所有者
    再决定是否卸载 Mesh、Material、SceneAsset 等资源

## 内部一致性与专项检查

- **32 B AoS 与分段 Buffer**：一致。32 B 是逐株记录段中的 AoS stride；整张 GraphicsBuffer 再按风场、逐株记录、每 Heap 量化表和两张稀疏光照表分段。两者不是 AoS/SoA 冲突。
- **两个 128 B**：区分明确。旧布局是 `128 B/instance`；当前仍保留的是 `128 B/Heap` 光照量化表。总节省只来自逐株段每株减少 96 B，文中也明确总 Buffer 降幅通常小于 75%。
- **Query Heap 与 Streamer Heap Bounds**：没有混淆。Query 路径当前错误复用不含外伸碰撞体的视觉 Bounds，存在假阴性；Streamer 路径则从 Shape→Instance→Heap 做保守并集，当前包含链成立。
- **HeapMask**：始终是渲染候选政策，不是物理卸载、QueryWorld 可见性、Buffer 紧凑或资源释放。
- **Rebase**：方向统一为 `delta=newAbsolute-oldAbsolute`、运行坐标减 `delta`。累计绝对偏移和单次增量没有混用；Cell 根变换与 Origin delta 的双重施加也被明确禁止。
- **正常卸载与 CleanupFailed**：区分明确。只有每个实际注册 Heap 获得已解除所有权结果，才允许继续 Dispose QueryWorld 并发布 Unloaded；异常路径当前实现达不到强保证，被如实列为生产阻断。
- **时代边界**：没有串代。历史 Quest A/B/A 是旧 StaticLightColor 系统；当前 32 B ABI 只有 Windows Editor D3D11/回读/Forward 证据；Quest Vulkan 未重测；Bakery 作者链没有因消费端改为 32 B 而重新跑完整验证；历史 Collider A/B 又单独限定为 Windows Editor 和无源码身份材料。
- **架构一般性与当前参考策略**：统一架构允许分页、多 Batch；ABI 篇描述当前单 Batch、单 Buffer 参考实现。两者是一般模型与具体策略关系，不是冲突。

## Heap 查询效率优化沉淀质量

该专题已经形成一篇可定位、可理解、可复用的独立记录：

- 标题直接包含 Heap–Shape、两级懒建 BVH、复杂度、性能证据和正确性前提，检索定位清楚。
- 独立定义 QueryWorld、Heap、Shape、Purpose、StableGuid、阈值和窄相位，不要求读者知道来源项目。
- 清楚区分 `<64` 线性与 `>=64` 懒建 BVH，叶容量 8 被标为参数而非通用真理。
- 构建复杂度准确写为 `O(n log² n)`，没有套用常见 BVH 的 `O(n log n)`。
- 查询复杂度只在良好分布、预热、局部稀疏时写为 `O(log n + K)`；最坏情况仍披露为 `O(H+S)`。
- `0 B` 只覆盖 65 Heap×64 Sphere、预热 16 次后、256 次单目标 Overlap 的 Windows Editor 线程增量；明确不覆盖冷建、扩容、Ray/Sweep、多 Cell 和 Quest。
- `55.1869×` 只描述 4096 个一维等间距 AABB、预热后、固定顺序、单层宽相位的一次聚合观察；缺 CPU、方差、随机交错、目标设备等限制均已披露。
- 最关键的生产正确性缺口——QueryHeapBounds 未包含全部 Query Shape——位于摘要、正确性章节、清单和验证记录，未被性能数字掩盖。
