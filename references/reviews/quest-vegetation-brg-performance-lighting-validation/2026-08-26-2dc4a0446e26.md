### 3. BRG 与普通 GO 光照差异

- BRG 的 `StaticLightColor` 在每株 `VisualRootSpaceBounds.center` 获取完整 L2，沿实例局部向上方向预求最终 RGB，存入 SceneAsset/Heap，运行时直接读取。
- 普通 GO 展开 GameObject、Transform、MeshRenderer、LODGroup，使用 GPU Instancing 和 BlendProbes；Bakery 非 Lightmap Shader 路径消费 `unity_SHAr/Ag/Ab` 的 L0/L1 表示，并按顶点法线进行 Geomerics 重建。
- 两条路径在颜色表达和运行成本上不严格等价，所以四组是完整系统路径比较，不是只替换 Draw API 的微基准。
- 场景逐株光照归属 SceneAsset/Heap；可复用 Prototype 只保存 Mesh、材质、LOD、Bounds、碰撞和光照模式声明。

### 4. v4 的 8 B/20 B 光照记录

两种模式都只在每株中心采样一次：

- `StaticLightColor`：8 B/株，存最终颜色，运行时不按顶点法线重算。
- `StaticBakerySh`：20 B/株，存 Bakery Ar/Ag/Ab，运行时按顶点法线执行 Geomerics L1。

8 B/20 B 只是稀疏光照 payload，不是完整实例 GPU 成本。v4 已移除 Root/Top 双高度格式，Lightmap 也不在当前枚举中。`StaticBakerySh` 没有进入四组历史 APK。

历史大 Box 报告仍是旧格式：Root 静态 RGB `98304/8192 = 12 B/株`，Top 为 0。这进一步阻止了把 v4 倒灌成历史 APK 条件。

### 5. 128 B→32 B 逐株 ABI

2026-08-26 候选把固定逐株区由 128 B 收敛到 32 B：

- 世界位置保留 float32。
- 旋转采用 smallest-three `10:10:10:2`。
- 统一缩放、风动和 Bounds 连续参数采用 Half 或 UNorm16。
- HeapIndex、光照模式和稀疏记录索引为整数位段。
- 另加所属模式的 8 B 或 20 B 光照 payload。
- 每 Heap 有 128 B 光照量化参数。
- Cell Buffer 另含 96 B 头部、空表合法寻址、哨兵和 16 B 对齐。

记录明确限定这些数字只覆盖一块静态 GPU Raw Buffer，不包括 CPU 快照、Persistent NativeArray、BRG Metadata、Mesh/Material、可见列表、临时 Job 数据或驱动副本。

### 6. 两组 8192 实例 Editor 回读

- 50 Heap、全静态颜色：旧公式 `1,120,640 B`，新逻辑 Buffer `334,208 B`，下降 `70.177%`。
- 1024 Heap：旧公式 `1,245,312 B`，新逻辑 Buffer `458,880 B`，下降 `63.151%`。

`Layout.TotalBytes`、底层 `count × stride` 和整段回读长度一致，只证明 Editor 中的逻辑分配和上传载荷一致，不证明：

- Quest 驱动实际物理图形内存按同比例下降；
- 整进程 PSS 同比例下降；
- 带宽、功耗或帧耗获得同比例收益；
- 新 Shader 的四元数恢复和向量旋转 ALU 已获得净收益。

### 7. HeapMask、Count/Scatter 与 Cell 卸载

- `ActiveHeapMask` 只阻止失活 Heap 生成可见引用，不缩小已上传的 Cell GPU Buffer。
- Count/Scatter 两遍 Job 仍按 Cell 总实例数调度，只在 Job 内对失活 Heap 提前退出。因此 Active Heap 减少不等于 CPU 迭代数同比下降。
- 独立 ColliderStreamer 管理碰撞代理，不直接读取渲染掩码。
- 只有完整运行时 Cell 卸载才释放该 Cell 的 BRG、Buffer 和 NativeArray。
- SceneAsset、Mesh、Material 是否释放，由外层 Scene 或资源句柄生命周期决定。

### 8. 内存、带宽、ALU 与帧耗边界

记录区分严格：

- **逻辑分配**：由布局公式、底层容量和 Editor 回读证明。
- **物理图形内存**：未测，不能由逻辑字节数直接推出。
- **PSS**：Android 整个进程的分摊内存，包含 Unity、XR、纹理、图形资源和分配器保留；GO 相对首段 BRG 的约 `75.473/45.568/66.998/40.193 MiB` 差值不能全部归因于 GameObject，也不能凭回切残留判断泄漏。
- **带宽**：较小 payload 只形成理论方向，未提供 Quest 设备带宽计数器。
- **ALU**：32 B Shader 解码增加四元数恢复和向量旋转成本，已明确列为代价。
- **帧耗、功耗和净收益**：均要求目标设备同协议 A/B，当前未验证。
- `App Frame` 与 `CPU+GPU` 均被定义为 VrApi 窗口指标，记录没有把前者当纯 CPU、后者当纯 GPU，也没有机械相加。
