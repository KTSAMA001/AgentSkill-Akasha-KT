2) 自己的话完整复述

文章要解决的核心矛盾是：大规模植被既不能让所有实例永久携带昂贵的真实 Collider，也不能因 Collider 未驻留而让玩法查询失效。为此，它把物理需求拆成两条互不替代的路径：

- 每个运行时 Cell 常驻一份 QueryWorld。它保存 Sphere、Capsule、定向 Box 等数学形状，直接完成 Raycast、Overlap、Sweep，不创建 Collider，也不产生 PhysX 接触或 Trigger。
- 每个运行时 Cell另有独立 ColliderStreamer。它根据玩家、手、载具等兴趣源，按 FixedUpdate 动态维持附近真实 PhysX Collider 的工作集，并通过对象池复用承载 Collider 的 Proxy。ConvexMesh 只走这条路径。
- 渲染 Heap 激活、解析查询和真实 Collider 流送是三种独立策略，不能用渲染掩码或某条路径的状态推断另一条路径是否可用。

一个运行时 Cell拥有自己的管理器、SceneAsset、QueryWorld、ColliderStreamer 和 ProxyPool。加载时，编排器先在局部创建 QueryWorld，逐 Heap 从共同的 Prototype、StableGuid 和变换数据构造解析形状与 Collider 描述；两路都完成后才能继续，全部成功后才发布 QueryWorld。空 Cell、只有查询形状或只有 PhysX 形状都属于合法加载结果。不同 Additive Scene 的 Cell 不共享 Streamer、池、预算或卸载责任。

当前加载正常路径可以解释清楚，但异常所有权还未闭环：`RegisterHeap` 可能先移除旧内容并部分写入新实例，调用方却只记录正常返回的注册。因此生产接入必须选择原子注册或显式事务/租约，并用失败注入证明失败后只可能保留完整旧版本或完整新版本。另一个已明确指出的当前正确性缺口是 QueryWorld 直接采用主要源自视觉范围的 Heap Bounds，没有保证其包含全部外伸 Query Shape；这可能在 Heap 粗筛阶段造成假阴性，必须独立聚合 Query Shape Bounds。

流送固定步的完整过程是：每个 Streamer 捕获兴趣源快照；以预测运动线段先筛 Heap，再计算实例的 Desired/Retain 引用；按高速来源、优先级、距离和 StableGuid 排序待激活实例；在每 Cell 的实例预算内激活，且一个多 Shape 实例会一次取得多个 Proxy；离开卸载半径后进入 Cooldown，到期归还池；本步有物理变更时统一同步 Transform。加载/卸载双半径形成滞回，Retain 只能保留已有代理，不能让未激活实例首次激活。AllResident 是小场景或 A/B 模式，会跳过流式激活上限。多 Shape 激活还必须具备实例级事务语义，失败不能留下部分激活状态。

多个 Cell 共用兴趣源注册表，但每个 Cell 独立捕获、评估并应用自己的半径、预算和池。卸载 B 只应释放 B，不影响 A。若玩法查询需要同时覆盖多个 Cell，外层协调器必须先固定活动 Cell 集合并持有 QueryWorld 生命周期，再将每条命中绑定到 `(RuntimeCellIdentity, StableGuid)`。Raycast/Sweep 先求严格最小距离，再在 `0.0001 m` 容差内以身份键收尾；Overlap 合并后按复合身份去重并稳定排序。当前单 Cell API 尚没有 RuntimeCellIdentity，也仍以浮点精确相等处理部分并列，所以这部分是生产契约，不是已实现事实。

Floating Origin 采用单一方向约定：绝对原点偏移增加 `delta` 时，运行对象平移 `-delta`。合法迁移必须暂停旧世代查询和固定步，让 QueryWorld、Streamer 数据、已借出 Proxy、兴趣源与渲染进入同一坐标世代，丢弃旧候选，再同步并恢复。当前只有 QueryWorld 和 Streamer 各自的局部增量入口，尚无 Cell 级原子广播和失败回滚，因此仅在使用 Floating Origin 的项目中需要补齐该协调层。

卸载成功路径由 `UnregisterHeap` 唯一负责归还 Proxy、清状态和移除 Heap，然后才释放 QueryWorld。异常时生产契约要求强清理结果；未确认清理的项必须保留原 Streamer、HeapGuid 和诊断并进入 `CleanupFailed`，不能清空记录后宣称 Unloaded。当前正常卸载职责成立，异常注销尚未满足这一要求。

性能部分没有把“减少 Collider”误写成“查询一定更快”。Streamer 的固定步成本按所有活动 Cell 累加，扫描、引用聚合、候选排序、Proxy 变化和多次 `Physics.SyncTransforms` 都不受单 Cell 激活预算完整约束。QueryWorld 则常驻全部解析形状及索引：小集合线性扫描，达到阈值后懒建两级 BVH；良好分布可降低候选量，但最坏仍是全扫描，首次建树和重建还有额外峰值。对象池也只有稳态复用收益，首次扩容必须单独测量。
