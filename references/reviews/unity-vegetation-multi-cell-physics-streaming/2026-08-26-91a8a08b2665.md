## 系统复述

这套架构把植被物理拆为两条互补路径：

- `QueryWorld` 常驻解析 Sphere、Capsule、Box，用于 Raycast、Overlap、Sweep；其结果不依赖真实 Collider 是否已流送。ConvexMesh 不进入解析查询。
- `ColliderStreamer` 仅为兴趣源附近实例创建真实 PhysX Collider Proxy，用于刚体接触和 Trigger。
- 每个运行时 Cell 独占 QueryWorld、Streamer、ProxyPool、半径、预算及卸载生命周期。多个 Cell 共享兴趣源快照，但不共享查询树、代理池或调度预算。
- 当前没有跨 Cell 的全局物理调度器，因此整世界单步激活上限近似为各 Cell 预算之和；多个 Streamer 还可能分别调用 `Physics.SyncTransforms`。

Cell 加载时，从相同 SceneAsset、Prototype、StableGuid 和 Cell Transform 派生两套数据。Query 侧注册解析 Shape，Streamer 侧注册可生成 PhysX Collider 的实例描述。空 Cell、仅查询 Shape、仅 PhysX Shape 都合法。只有全部 Heap 处理成功后才发布 QueryWorld 加载句柄；失败或卸载时，按实际成功注册列表逆序反注册、归还代理并释放 QueryWorld，避免依赖后来可能被 Inspector 改写的引用。

一个实例可以有 N 个 Collider Shape。流送状态和激活候选按实例推进，但激活后会在同一次 `Activate` 中为全部 N 个 Shape 取得 N 个 Proxy。因此：

- `maxActivationsPerFixedUpdate` 限制的是新激活实例数，不是 Collider/Proxy 数。
- 单步新增 Proxy 数没有仅由该预算给出的固定上限。
- 实例退出后，其全部 Shape Proxy 一并进入归还生命周期。
- Pool 按 Shape 类型复用 Proxy；历史证据只覆盖归还后的复用，不覆盖冷池首次扩容峰值。

固定步中，多个兴趣源按实例聚合为 Desired 与 Retain 引用。进入 LoadRadius 同时产生 Desired、Retain；只处于 LoadRadius 与 UnloadRadius 之间则只有 Retain。Inactive 实例必须有 Desired 才能竞争激活预算；已有 Active/Cooldown 实例可由 Retain 保留。候选按“高速来源优先、Priority 降序、距离升序、StableGuid 升序”确定性排序，一个实例不会因多个来源重复消耗预算。

状态流转为 `Inactive → Desired → Active → Cooldown → Inactive`：

- 离开 UnloadRadius 才从 Active 进入 Cooldown。
- 冷却期重新进入 LoadRadius 或 UnloadRadius 保留区，立即回到 Active。
- 默认冷却 0.5 秒，按每次 FixedUpdate 的 `fixedDeltaTime` 递减；再次离开时重新从完整时长计时。
- 冷却为 0 时同一步归还全部 Proxy。
- Heap 注销或 Cell 卸载会绕过冷却，强制清理 Desired、Active、Cooldown。
- Streamed 模式预算为 0 只暂停新激活，不卸载现有代理；AllResident 跳过实例激活预算。

2025 快照中的 Heap/Shape 宽相位是线性枚举。123、1024、4096 Heap 的 Editor 空 Shape 数据只支持“成本随 Heap 数近似线性增长”的历史方向判断；缺少独立案例、CPU、几何分布及预热信息，当前也无法复跑，不能作为 Quest 或 2026 BVH 的对照基准。

2026 快照改为每个 QueryWorld 独立持有 Heap→Shape 两级懒建扁平 BVH：

- 数量少于 64 时线性枚举；达到 64 才建 BVH。
- 叶节点最多 8 项。
- 节点保存子树 AABB、连续索引区间及 Purpose Mask 位或，用于空间和用途剪枝。
- 顶层 Heap BVH 在第一次查询时构建；大 Heap 的 Shape BVH 延迟到该 Heap 首次成为候选。
- 增加、替换、移除 Heap 会使顶层索引失效，下一次查询按 HeapGuid 固定顺序重建。
- 全局原点平移不重建拓扑，以 `O(H + S)` 平移 Heap、Shape、缓存 Bounds 和已建节点。
- 候选容器、去重集合和遍历栈复用并保留历史峰值容量；实现假定单运行时线程串行访问，不支持查询期间并发注册。
- BVH 只生成候选，最终仍执行 Sphere、Capsule、OBB 窄相位；Sweep 每个候选最多进行 64 次保守推进。

复杂度陈述基本克制：当前建树因每层重新排序，上界是 `O(n log²n)`，常驻索引为 `O(n)`；预热、稀疏、分布良好时查询趋近 `O(log n + K)`，但全覆盖、大量重叠、同中心或超大 Bounds、长 Ray/Sweep 仍可能退化到 `O(H + S)`。内存除常驻 Shape Bounds/Purpose 与节点数组外，建树会先建立约 `Count × 2` 容量的节点 List，再复制到精确数组；冷建临时峰值、首次延迟、重建尖峰目前没有量化。ProxyPool 冷扩容也是独立的冷启动风险。

`4096 AABB、44.05×` 只适用于沿 X 轴稀疏排列、单候选 Bounds 查询、冷建树排除、两侧预热 32 次、各连续测量 2048 次的单组 Windows Editor 微基准。它不是旧 QueryWorld 完整实现的 A/B，也不包含两级查询、解析窄相位、首次建树、增删重建、随机交错、多次独立统计或 Quest Player。记录没有把它扩张为“完整系统提速 44 倍”。

“预热后连续 256 次单目标 Overlap 的 managed allocation 增量为 0”只覆盖该 Editor 线程上的 warm 路径；不覆盖首次建树、重建、结果容器扩容、Proxy 创建或整进程 GC。历史 Collider A/B 的 `0 B/步` 同样仅覆盖所定义的固定步核心区间。

最重要的已确认正确性问题是 Query Heap Bounds 使用视觉 Bounds，而 Query Shape 由独立碰撞描述产生。视觉 Bounds 没有保证包住全部 Query Shape；外伸 Shape 所在 Heap 可能先被粗筛拒绝，造成确定性假阴性。线性和 BVH 都受影响，现有测试还没有建立生产数据包含关系门禁。记录提出的方向——独立构建 Query Heap Bounds，或聚合视觉 Bounds 与全部 Query Shape Bounds并补外伸回归——合理。

其余明确风险包括：

- 同实例多 Shape 共用 StableGuid，Overlap 去重及阈值前后候选顺序变化可能让 Point、Normal、ShapeType、Purpose 等接触详情不稳定。
- NaN/Infinity 未统一拒绝，可能污染 Bounds 并造成错误剪枝。
- Sweep 容差与 AABB 粗筛膨胀不完全一致，擦边、零距离、极大坐标、重复原点漂移尚缺门禁。
- 63/64 阈值两侧、长查询、重叠退化、多 Cell 实际负载、Quest 主线程时间和全局预算均未验证。
