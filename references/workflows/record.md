# 记录与归档流程

> 把原创经验、知识、创意或公开资料保存为正式记录。本流程不修改模板、workflow、schema 或索引规则；系统变更转 [governance.md](./governance.md)。

## 1. 执行总览

1. **确认记录意图与授权**：用户直接要求记录时按该范围执行；若是 Agent 主动建议，必须先征得同意。联网获取来源、删除、提交和推送分别遵循当前授权。
2. **检查当前状态**：确认仓库、分支、远端和工作树；若本次包含发布，在写入前安全同步远端，遇到分叉或重叠改动就停下处理，不自动改写历史。
3. **记录前检查**：在 `data/*.md` 中检查重复或冲突，核对事实、来源、时效、适用范围和敏感信息。
4. **预览并确认**：向用户展示标题、概要、记录类型、主要来源、脱敏结论和目标文件；确认后再写正式候选。
5. **完成候选与资源**：按 [record-template.md](../templates/record-template.md) 写入 `data/<record-name>.md`，先保存正文直接引用的资源并改为相对路径。
6. **机器检查**：按 [scripts/README.md](../scripts/README.md) 运行首轮结构校验；除本次记录导致的预期索引差异外，其他错误先修复。
7. **陌生读者审核**：冻结候选和直接引用资源，按 [reviews/README.md](../reviews/README.md) 完成无历史只读冷读。未得到“可发布”时只按新证据做定向修订；复审仍是同一阻断且没有新证据就停止并报告，不能机械循环。
8. **同步索引并复验**：用脚本重建 `INDEX.md` 文件清单；有新标签时更新 `tag-registry.md`，随后再次校验。
9. **发布与报告**：仅在授权范围内精确暂存本次文件、提交和推送；核对真实结果后报告已完成范围、未发布原因或剩余风险。

写入 `data/` 的内容必须是正式成品，禁止草稿、占位符、临时片段和“以后补”的半结构记录。信息不足时应补充调查或等待必要输入，不降低正式库标准。

## 2. 记录前检查与预览

### 重复、正确性与来源

- 按主题、术语、标签和近义词检索 `data/*.md`，判断是新增、补充现有记录还是存在冲突。
- 区分直接证据、可靠转述、推断和未知；结论强度不得超过证据。
- 对版本敏感或可能已变化的信息核对适用版本、来源日期和当前状态。
- 与已有记录矛盾时，不静默覆盖；按 [validate.md](./validate.md) 的冲突策略处理。

### 敏感信息语义审查

检查原始上下文、摘要、正文、代码、命令输出、路径、资源名和链接。常见敏感信息包括：

- 真实内部项目、仓库、分支、目录结构和本机绝对路径；
- 账号、邮箱、手机号、token、API key、密码、私钥和凭据内容；
- 客户、人员、未公开业务背景，以及可反推出内部资产的标识符。

发现后先泛化、替换占位符、删除或改写为可复用结论。预览只说明敏感信息的类型、位置概览和处理方式，不复述完整值。用户要求保留不应进入共享知识库的信息时，不得写入数据层。固定模式扫描只能辅助告警，不能证明“没有敏感信息”。

### 用户可见预览

写入前至少展示：

- 拟记录标题和一段概要；
- 原创整理或学习用途本地留档；
- 主要信息来源与当前证据边界；
- 脱敏检查结果和拟采用的处理；
- `data/<record-name>.md` 及预计新增的资源目录。

## 3. 分支 A：原创整理

原创经验、知识、创意和参考资料都使用同一模板，以 `type` 标签区分。正文结构随内容选择：

| 类型 | 正文应解决的问题 |
|---|---|
| 经验 `#experience` | 场景和症状是什么；根因是什么；方案为何有效；如何验证；何时不适用 |
| 知识 `#knowledge` | 概念是什么；前提和机制是什么；证据或推导如何支持结论；如何应用；边界是什么 |
| 创意 `#idea` | 灵感来自哪里；核心想法是什么；可行性、风险、验证方法和下一步是什么 |
| 参考 `#reference` | 资料解决什么需求；如何查用；版本和来源是什么；哪些内容未经验证 |

### 写作质量

- 按**知识博客或技术/学术论文**的方式组织，而不是把对话、日志或零散检查项原样堆进去。
- 开头尽早交代适用场景、真实问题、目标结果和核心结论。
- 首次出现的术语要用目标读者能理解的语言解释；必要时给出定义、公式、图表、代码或完整例子。
- 论证过程区分证据、推断和假设；关键数字、兼容关系和因果链应有来源或验证方式。
- 架构与流程主题给出端到端路径：输入如何经过组件成为用户可观察的输出，并说明失败方式、恢复、取舍与代价。
- 结尾收束成可执行步骤、采用检查、适用/不适用条件、风险、结论或下一步。
- “参考链接”和“相关记录”只作补充，当前正文脱离它们也应成立。
- 篇幅与主题复杂度匹配；简短事实可以简短，不为门禁机械堆砌章节。

## 4. 分支 B：学习用途本地留档

当用户要求“学习留档”“离线保存”“原文保存”，或需要避免公开网页失效时使用。适用来源包括公开博客、技术文档、论坛文章和论文网页。核心原则是：**完整保存公开原文与内容资源，不改写原文。**

### 适用与边界

- 适用于公开博客、知乎、论坛文章等供个人学习、研究或离线查看的内容。
- 只归档用户有权访问且允许在当前范围处理的内容；登录态、付费墙或非公开资料不能因本流程绕过访问控制。
- 无法验证正文完整性、资源缺失或抓取被截断时，必须说明“归档不完整”并列出缺失项；只有能在当前授权内安全取得时才补齐，不能反复抓取，也不能把摘要、节选或单个链接称为完整留档。

### 4.1 获取完整原文

1. 使用当前可用的页面读取或下载工具取得正文。可用时可选择站点下载工具；若结果被截断，可在获得相应权限后通过浏览器提取正文。
2. 对照原页面检查标题、章节顺序、开头和结尾、段落、列表、表格、代码块、引用块和内容图片，确认没有静默截断。
3. 保存来源 URL、作者/平台信息和来源日期；无法确认的字段明确标为未知，不编造。

### 4.2 保存内容资源

- 提取所有对理解正文有作用的图片或附件，排除头像、广告、推荐卡片和网站装饰。
- 保存到 `assets/<record-name>/`，按正文出现顺序命名为 `01-description.ext`、`02-description.ext`。
- 下载防盗链资源时可按来源要求设置 `Referer` 和 `User-Agent`；失败时报告具体缺失项。
- 把原文资源链接替换为本地相对引用：`../assets/<record-name>/01-description.png`，并写有意义的 alt 文本。
- 图片较多时可在文末列出资源清单；非 `data` 层历史文件归档到 `assets/archives/`。

### 4.3 写入记录

记录由“本地包装”和“原文正文”组成：

- 本地包装：标准元数据、1–2 句概要、来源链接、相关记录和验证记录。
- `### 内容`：按原顺序完整保留正文，包括标题层级、段落、列表、表格、代码块、引用块和本地化图片。

禁止：

- 改写、缩写、概括、调序或省略原文段落和章节；
- 把作者分析、修正或冷读意见插入原文；补充说明只能放在 `### 内容` 之外；
- 只保存摘要、链接或部分图片，却声明“完整原文归档”。

陌生读者冷读只审核本地概要、元数据、导航、来源说明、资源完整性和适用边界。若原文依赖外部背景，在本地包装中说明；不得为了通过审核篡改原文。

## 5. 文件、标签、资源与引用

### 文件

- 位置固定为 `data/*.md`，不创建子目录。
- 文件名使用全小写、自解释的 `kebab-case`，例如 `urp-renderer-feature-custom.md`。

### 标签

- 每条记录至少包含 1 个 `domain` 和恰好 1 个 `type`，可以增加 `specialty`、`custom`。
- 先查 [tag-registry.md](../tag-registry.md) 并优先复用；新标签必须注册维度和说明，避免一次性标签膨胀。
- 新标签同时影响标签注册表和 INDEX 标签概览；文件清单仍由索引脚本生成。

### 资源与相关记录

- 普通正文资源放在 `assets/<record-name>/`，正文禁止绝对路径和越界引用。
- 资源变化会使既有冷读摘要失效；冻结后不得偷偷替换同名文件。
- 记录间使用 `./other-record.md`，并说明关联原因；相关记录不能承担当前正文的必要解释。

## 6. 陌生读者冷读

新增正式记录，以及标题、概要、状态、正文结构、技术数字、代码、步骤、方案、因果链、适用范围或结论发生实质变化的候选，都必须执行冷读。

冷读的唯一证据规范是 [reviews/README.md](../reviews/README.md)。核心门禁保持如下：

- 使用不继承撰写对话的新只读上下文，输入仅限冻结候选、直接引用资源、目标读者画像和审核问题；
- 绑定记录与资源的完整 SHA-256，读者在阅读前和结论前各自重算；
- 保存完整提示、输入白名单、上下文 ID、起止摘要和未经删改的原始输出；
- 结论只能是“可发布”“修改后发布”“无法判断”，后两者均阻断；
- 发布前再次复算。资源变化或语义变化必须重新完整冷读；纯机械修正只能按 reviews 规范由非作者复核并形成连续证据链。

脚本通过、作者自评、让参与撰写的 Agent “假装陌生”，以及一句“已审阅”，都不能替代该门禁。

## 7. 机器检查、索引与发布

按 [scripts/README.md](../scripts/README.md) 执行：

```bash
python3 references/scripts/validate_records.py
python3 references/scripts/regenerate_index.py
python3 references/scripts/validate_records.py
```

- 第一次校验发现结构、标签、路径或非预期索引错误时先修复。
- 索引脚本只重建 `INDEX.md` 文件清单，不修正文义，也不证明冷读或脱敏通过。
- 使用新标签时同步 `tag-registry.md` 和 INDEX 标签概览；第二次校验确认最终一致性。

若当前授权包含 Git 发布：

1. 写入前检查工作树，并以快进方式同步目标分支；冲突或分叉时停止，不自动 rebase、stash、reset 或覆盖用户改动。
2. 冷读和脚本链通过后查看精确 diff，只暂存本次记录、资源、审核证据、索引及必要标签文件。
3. 提交标题使用仓库约定；无更具体约定时可用 `docs: add <record-name>`、`docs: update <record-name>` 或 `fix: correct <record-name>`。
4. 推送后核对提交与目标远端；失败时保留可恢复状态并报告真实原因，不把“本地已写入”说成“远端已发布”。

## 8. 完成检查

### 所有记录

- [ ] 意图、授权、重复、事实、时效、来源和脱敏检查已完成。
- [ ] 用户已看过并确认记录前预览。
- [ ] 正式候选位于 `data/*.md`，结构、标签、状态和相对路径符合模板。
- [ ] 原创正文达到知识博客或技术/学术论文的独立可读性。
- [ ] 最终候选有匹配 SHA-256 的“可发布”证据，或合规的连续机械继承链。
- [ ] 已运行“校验 → 索引生成 → 再校验”，新标签已注册。
- [ ] Git 动作只在授权范围内执行，且没有夹带无关改动。

### 离线留档额外检查

- [ ] 原文标题层级、顺序、段落、表格、代码、引用和结尾均完整保留。
- [ ] 所有正文内容资源已本地保存并替换为相对路径；缺失项没有被隐瞒。
- [ ] 来源 URL、来源日期和本地概要齐全。
- [ ] 冷读没有改写原文，只审核本地包装、导航和完整性。
