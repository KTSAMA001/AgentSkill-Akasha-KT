# 系统治理流程

> 只用于调整阿卡西系统层规则。普通知识记录和已有记录修正不得借此扩大为系统重构。

## 1. 适用范围

下列变化进入治理流程：

| 类型 | 示例 |
|---|---|
| Skill 路由 | 意图识别、数据/索引/系统边界、全局完成条件 |
| Workflow | search、record、validate、governance 的步骤与责任 |
| 记录契约 | 模板字段、章节、状态、可信度、路径和 Web 解析约定 |
| 标签与索引 | 标签维度、注册规则、INDEX 生成和校验规则 |
| 工具与审核 | 维护脚本能力、冷读门禁及证据格式 |
| 历史整治 | 批量迁移、结构修复、标签合并或兼容计划 |

知识查询仍只可返回 `data/*.md`。系统文档、索引和审核证据不能因治理任务而变成用户知识来源。

## 2. 开始前固定边界

1. 明确用户要解决的问题、可观察完成标准、非目标和停止条件。
2. 以未改动的当前基线盘点现有能力、规则权威和消费者，不能把候选版本当成原始要求。
3. 列出精确读写集合。默认保护 `data/**`、`assets/**`、历史 `references/reviews/**` 和 INDEX 的知识内容；需要迁移时另行说明并取得授权。
4. 记录仓库、分支、基线提交和现有未提交改动；不得覆盖、回退或夹带用户改动。
5. 区分纯文档澄清、等价结构重排、兼容增强和破坏性契约变更。只有明确授权后才能扩大类型。

## 3. 执行步骤

1. **建立功能清单**：把现有查找、记录、离线归档、验证、冷读、索引、标签、Git 和治理能力逐项映射到权威文件。
2. **定位真实问题**：找重复、循环依赖、自相矛盾、过时示例和无法验证的要求；不要用删功能解决文档太长。
3. **设计职责归属**：入口只负责路由和跨流程边界；workflow 负责操作步骤；模板负责记录结构；reviews 负责冷读证据；scripts 负责机器检查。避免同一规则在多个地方完整重述。
4. **评估兼容性**：检查历史记录、标签、INDEX、脚本、安装方式和 Web 消费者是否仍按原契约工作。
5. **在隔离候选中修改**：只改必要系统文件；不让其他 Agent 读取正在编辑的中间态，也不触碰知识数据。
6. **交叉核对**：检查路由、链接、schema、状态枚举、标签维度、脚本说明和实际代码是否一致；确认主流程没有互相回跳。
7. **验证功能等价与副作用**：执行适合风险的场景检查、脚本链和差异审计；结构校验通过不等于用户功能等价。
8. **独立复审**：由未参与修改、无当前实现历史的只读审查者检查缺失能力、自相矛盾、弱门禁、可绕过路径和无谓复杂度。
9. **同步正式候选并报告**：按授权决定是否只保留本地改动、提交或推送；明确已验证范围、未验证消费者、兼容风险和后续动作。

新证据否定原方案时立即调整，不机械完成旧计划。同一路径反复失败且没有新证据时停止重试，交付阻断点和可恢复路径。

## 4. 兼容性检查

- 四类主意图及其触发语义是否仍存在。
- 查询是否仍严格限定 `data/*.md`，本地未命中是否仍为条件式联网。
- 原创记录、完整公开文章离线保存、内容资源与相对路径是否仍可执行。
- 模板字段、八种状态、可信度、标签维度和 Web 映射是否保持兼容。
- 正确性、时效性、来源、脱敏、资源、可读性和冲突处理是否仍保留。
- 无历史冷读、SHA-256、原始输出、三种结论、发布前复算和机械继承证据是否仍闭合。
- `validate → regenerate INDEX → validate`、新标签同步和受控历史迁移是否仍可用。
- Git 同步、精确提交、推送和失败报告能力是否保留，同时不夹带无关改动。
- `data/**`、`assets/**`、历史审核证据和未授权的索引内容是否保持不变。

## 5. 验证要求

治理变更完成后，至少执行：

```bash
python3 references/scripts/validate_records.py
python3 references/scripts/regenerate_index.py
python3 references/scripts/validate_records.py
```

- 在隔离副本运行会写 INDEX 的步骤，并核对生成前后差异；不得让测试污染正式数据。
- 历史存量问题要与本次引入的问题分开报告；不能把“脚本能运行”误写成“数据全部合规”。
- 检查全部相对 Markdown 链接、关键路由场景和变更文件清单。
- 若变更记录、验证或审核门禁，独立审查者必须专门检查作者自评、继承历史、弱断言、缺失证据和跳过复审等绕过路径。
- 若影响 Web 或其他外部消费者，在环境和授权允许时做消费者验证；无法执行就明确未验证边界。

## 完成检查

- [ ] 本次确属系统治理，目标、非目标、基线和写集合明确。
- [ ] 原版功能逐项有去向，没有以“精简”为名删能力。
- [ ] SKILL、workflow、模板、reviews、scripts、INDEX/tag 和消费者之间无已知冲突或循环。
- [ ] 数据、资源、历史证据和用户已有改动没有意外变化。
- [ ] 脚本链、链接、功能场景和独立只读复审均已按风险执行。
- [ ] 结果说明了系统层改动、兼容策略、验证边界、剩余风险及真实 Git 状态。
