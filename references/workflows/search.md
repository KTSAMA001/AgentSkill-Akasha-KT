# 查找流程

> 从已提交的阿卡西记录中查找经验或知识。本流程默认只读、离线，不触发记录或发布流程。

## 1. 固定边界

- 必须实际检索，禁止凭模型记忆回答“阿卡西里有没有”。
- 唯一可搜索并作为知识返回的范围是 `data/*.md`。
- `SKILL.md`、`README.md`、`references/**` 和 `assets/**` 不能独立成为知识命中；即使其中出现关键词，也按本地未命中处理。选中 `data/*.md` 后，可以读取或展示该正文直接引用的资源。
- 不把 `references/INDEX.md` 全文作为检索上下文发送给模型。
- 查询不得修改文件、重建索引、执行 Git 同步或主动创建记录。

## 2. 本地查询

1. 从问题提取主题、技术名、症状、版本和可能的标签。
2. 仅在 `data/*.md` 中按文件名、正文关键词和标签检索；先用精确词，再用同义词或更宽的概念。
3. 读取最相关的命中记录，而不是只根据文件名或搜索片段作答。
4. 检查记录的状态、来源/更新日期、适用版本和已声明边界。
5. 输出命中内容、文件来源和适用性判断；若多条记录冲突，呈现差异，不擅自拼成单一结论。

### 命中优先级

| 检查项 | 默认处理 |
|---|---|
| 相关度 | 核心概念、症状和环境均匹配的记录优先 |
| 状态 | 优先采用 `✅ 已验证`、`📘 有效`；其他状态必须显式提示 |
| 版本 | 当前环境不在适用范围内时，不直接套用 |
| 日期与来源 | 时效敏感主题优先较新、较权威并有验证记录的内容 |

## 3. 本地未命中

若没有 `data/*.md` 命中，必须先明确说：**“阿卡西本地未命中。”**

- 用户只问“以前是否记录过”时，到此结束。
- 用户明确要求继续查资料，或原问题本身就是外部调研任务时，才进入下一节。
- 只有系统层文件命中，仍视为本地未命中。

## 4. 条件式外部调研

1. 先说明本地未命中以及将继续外部调研。
2. 根据问题选择可用搜索工具，优先官方文档、标准、论文或项目一手资料，其次是官方论坛和高质量社区资料。
3. 检查版本、发布日期、来源权威性、示例完整性和相互冲突的证据。
4. 在回答中明确标注这是**外部调研结论**，不能写成阿卡西已有记录。
5. 若结论值得沉淀，可以建议记录；只有用户明确同意后，才另行进入 [record.md](./record.md)。

网络不可用、来源无法访问或证据不足时，如实说明，不用模型记忆补成已核实事实。

## 5. 输出要求

- 清楚区分“阿卡西本地记录结论”与“外部调研结论”。
- 引用本地记录时说明状态、版本适配和重要限制。
- 没有命中就明确报告，不制造库存知识。
- 只回答当前问题，不因查询自动改库、更新 INDEX 或发布 Git。

## 完成检查

- [ ] 实际检索范围只有 `data/*.md`。
- [ ] 已读取命中正文并检查状态、日期和版本。
- [ ] 未命中时已明确告知，并且没有越过联网授权。
- [ ] 若执行外部调研，已将其与本地知识分开表述。
- [ ] 全程没有写文件或触发发布副作用。
