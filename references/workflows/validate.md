# 验证流程

> 验证已有记录的正确性，必要时进行修正

## ⛔ 执行约束（强制）

- 允许修改 `data/*.md`、配套 `assets/<record-name>/*`、冷读证据 `references/reviews/*`、[INDEX.md](../INDEX.md) 与 [tag-registry.md](../tag-registry.md)；禁止在技能目录外操作。
- 必须先执行 `git pull origin main`，再进行验证与修正。
- 若标签或状态变化，必须同步更新 tag-registry.md（如新标签）。
- 验证流程仅处理正式记录及其索引同步，不负责修改模板、workflow、字段 schema 或其他系统层规则；此类变更必须转入 [governance.md](./governance.md)。
- 完成修正后必须执行 `git commit && git push`，或明确说明未推送原因。

## 强制脚本

- 全库巡检**必须**运行 [validate_records.py](../scripts/validate_records.py)，集中检查标签、状态、元数据、路径和索引一致性。
- 若记录内容已修正完成，**必须**运行 [regenerate_index.py](../scripts/regenerate_index.py) 同步文件清单，并再次执行校验确认无误。
- 脚本使用说明**必须**遵循 [scripts/README.md](../scripts/README.md)。

## 一、验证类型

| 类型 | 说明 |
|------|------|
| **正确性** | 内容是否仍然有效、准确 |
| **时效性** | 版本/环境变化是否影响适用性 |
| **来源性** | 来源是否权威、是否有更新 |
| **完整性** | 标签是否齐全、格式是否规范 |
| **资源完整性** | 引用的图片/资源文件是否存在、路径是否正确 |
| **结构一致性** | 元数据字段、状态枚举、相对路径格式是否仍符合正式结构契约 |
| **敏感信息与脱敏审查** | 是否包含不应进入阿卡西正式库的敏感信息，并确认已在写入前完成脱敏 |
| **可读性与读者独立性** | 目标读者能否在不知道当前对话、项目经历和作者隐含前提时，独立理解问题、机制、结论与边界 |

## 二、状态标记

| 标记 | 含义 |
|------|------|
| ✅ 已验证 | 经实践确认有效 |
| ⚠️ 待验证 | 理论可行未实测 |
| 📘 有效 | 信息准确且当前适用 |
| 🔄 待更新 | 有新版本/变更 |
| 📕 已过时 | 不再适用当前环境 |
| ❌ 已废弃 | 错误/有风险 |
| 🔬 实验性 | 非主流方案 |
| 💡 构想中 | 创意阶段 |

## 三、验证与修正流程

### 触发场景
| 场景 | 说明 |
|------|------|
| 引用验证 | 引用记录回答时检查适用性 |
| 用户反馈 | 收到"不对"、"过时"反馈 |
| 版本更新 | 技术框架有重大更新 |
| 矛盾检测 | 新记录与已有记录冲突 |
| 新记录写入 | 写入前检查重复、正确性、时效性与敏感信息暴露风险 |

### 脱敏审查原则

> 脱敏审查是语义质量门禁，不是固定格式脚本扫描的替代品。

- 新记录写入前必须检查原始上下文、拟记录摘要、代码片段、命令输出、路径、资源引用与参考链接中是否包含敏感信息。
- 敏感信息包括但不限于：真实项目名、内部仓库/分支/目录结构、本机绝对路径、账号、邮箱、手机号、token、API key、密码、私钥、凭据文件内容、客户/人员信息、未公开业务上下文、可反推出内部资产的资源名或标识符。
- 向用户提供记录前预览时，必须说明脱敏审查结果：是否发现敏感信息、发现的类型或位置概览、拟采用的脱敏方式。不得在预览中直接复述完整敏感值。
- 发现敏感信息时，应先将其泛化、替换为占位符、删除或改写为可复用技术结论，再进入正式写入；用户明确要求保留敏感信息时，不得写入共享阿卡西数据层。
- 脚本未命中固定高危模式，只能说明“未发现脚本覆盖范围内的问题”，不能作为“无敏感信息”或“脱敏已完成”的证明。

### 可读性与陌生读者审查原则

- 结构完整不等于文章可读。`validate_records.py` 只能验证字段、标签、路径和索引，不能证明因果连贯、术语已解释或结尾没有虎头蛇尾。
- 新增记录或正文实质改写必须按 [record.md](./record.md) 的“陌生读者冷读门禁”审查；必须使用不继承父任务历史的新只读上下文，冻结候选并绑定 SHA-256。作者自评、复用参与实现的 Agent 或一句“已审阅”不能替代该门禁。
- 审查首先要求读者复述其实际理解，再检查缺失背景、术语、端到端机制、适用边界和可执行收尾；不得先告诉读者“正确答案”后再询问是否读懂。
- 读者若给出“修改后发布”或“无法判断”，本轮即为阻断；修复阻断项、实质修订或资源变化必须让新候选重新获得“可发布”。只有满足机械规则的记录文本变化，才能凭完整连续继承链到达最终 SHA。证据必须包含任务/上下文 ID、完整审核提示、输入白名单、读者重算的起止摘要和未经删改的完整输出；发布前还须再次逐项核对记录与资源摘要。
- 经验类记录至少应说明“场景与症状 → 根因 → 方案为何有效 → 验证与边界 → 可复用结论”。架构类记录还应说明请求或数据的端到端路径、组件责任、兼容关系、失败恢复、迁移顺序与代价。
- 简短速查、术语表或单一事实记录可以保持简短，但仍需给出用途和适用范围；门禁不要求所有记录采用同一种长文结构。
- 相关记录和外部链接只作补充，不能用来替代当前正文中解释核心概念。

### 修正策略

#### 小幅修正（内容微调）
```markdown
**验证记录**：
- [YYYY-MM-DD] 修正：Unity 2022+ 需要额外配置 xxx
```

#### 重大修正（方案变更）
```markdown
**内容**：
[新方案内容]

<details>
<summary>📜 历史方案（已废弃）</summary>
...
</details>
```

## 四、交叉验证

> 不同记录之间的相互佐证

- **知识佐证经验**：记录经验时引用相关知识记录
- **经验验证知识**：用实践结论检验理论知识
- **冲突处理**：
  - 知识更新 → 更新知识记录 + 修正关联经验记录
  - 经验证伪知识 → 检查适用场景或标记过时

### 引用格式
```markdown
### 相关记录
- [相关记录](./other-record.md) - 关联说明
```

---

## 五、冲突处理策略

| 类型 | 策略 |
|------|------|
| **场景差异** | 保留两者，明确适用场景 |
| **版本差异** | 保留两者，标注适用版本 |
| **事实冲突** | 验证后保留正确的，废弃错误的 |

## 六、质量检查清单

- [ ] 标签完整？（≥1 领域 + 1 类型）
- [ ] 内容清晰易懂？
- [ ] 代码可运行且无误？
- [ ] 标注了适用版本/环境？
- [ ] 引用了官方/权威来源？
- [ ] 状态标记准确？
- [ ] 状态字段是否仍使用固定枚举，而非夹带说明性自由文本？
- [ ] 文件名自解释？
- [ ] 已更新 INDEX.md？
- [ ] 若新增标签，已更新 tag-registry.md？
- [ ] 图片资源完整？（引用的文件均存在于 `assets/<record-name>/`）
- [ ] 路径均为相对路径？（无绝对路径泄露）
- [ ] 图片命名规范？（`序号-描述.扩展名`）
- [ ] 已完成敏感信息语义审查？（脚本未命中不等于无敏感信息）
- [ ] 若发现敏感信息，是否已在记录前预览中说明类型/位置概览和脱敏方式，并在脱敏后再写入？
- [ ] 新增或实质改写正文是否直接获得最终 SHA-256 的“可发布”证据，或具有连接到最终 SHA-256 的连续机械继承链？
- [ ] 是否解释了目标读者不一定知道的术语、背景和隐含依赖？
- [ ] 结尾是否给出与记录类型相符的结论、行动、适用边界或下一步，而非停在内部测试结果？

## 七、更新操作

1. 🔴 **CRITICAL - 同步仓库**：`git pull origin main`
2. **定位记录** → 在 `data/` 目录下通过文件搜索或文本搜索定位记录
3. **执行更新**：
   - 更新"更新日期"字段
   - 修改状态标记
   - 在"验证记录"添加说明
4. **读者审查** → 正文发生实质变化时，冻结最终候选并按陌生读者冷读门禁审查；最终 SHA-256 必须直接获得“可发布”，或通过合规的连续机械继承链连接到最近一份“可发布”证据。只有不改变语义、Markdown 渲染结构、锚点、链接、代码和元数据的记录文本修正，才能在非作者复核并保存旧/新 SHA 与精确 diff 后继承既有结论
5. **更新索引** → 如标签或状态变化，同步更新 INDEX.md；如涉及新标签，同步更新 tag-registry.md
6. **推送更改**：`git add . && git commit -m "fix: update [文件名]" && git push`
7. **反馈用户** → 说明更新了什么

### 强制验证命令

```bash
python3 references/scripts/validate_records.py
python3 references/scripts/regenerate_index.py
python3 references/scripts/validate_records.py
```

- 未完成上述命令链路，不得声称“验证流程已完成”。
- 若脚本报错或返回非零退出码，必须先解释原因并继续修正，禁止跳过失败结果直接汇报成功。
